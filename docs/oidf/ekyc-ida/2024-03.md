# OpenID Foundation eKYC-IDA WG 活動レポート (2024年3月)

> 執筆日: 2026-05-22（遡及執筆）
>
> 本記事は 2024 年 3 月の活動を 2026-05-22 時点の視点で遡及的にまとめたものです。

## 1. 概要

eKYC & Identity Assurance Working Group（以下「eKYC-IDA WG」）は、本人確認済みクレーム（verified claims）と検証プロセスのメタデータを OpenID Connect 上で標準的に伝達する仕組みを策定する OpenID Foundation の WG である。中核仕様は **OpenID Connect for Identity Assurance 1.0 (OIDC4IDA)**、**OpenID Identity Assurance Schema Definition 1.0**、**OpenID Connect for Identity Assurance Claims Registration 1.0** の 3 本。

**2024 年 3 月は、3 仕様の Final 化プロセスを WG コンセンサスで正式に起動した節目の月** である。3/13 の定例 WG コールにおいて「**3 仕様（IDA Verified Claims / Connect 4 Identity Assurance / Connect 4 IDA Claims）の WG Final Call** を実施する」ことについて参加者全員の合意（コンセンサス）が成立し、Gail Hodges（OIDF Executive Director）が「Great news! A big milestone for the WG」と称賛するメールを ML に投稿した。これにより 4 月以降の「Final Call Issues & PRs 編集消化フェーズ」へと進む下地が整った月にあたる。

当月の流れを整理すると次のとおり:

- **3 月 6 日コール**: 当月最初の定例。OIDC4IDA の Final 移行を主議題に据え、Issue #1363（ISO 構造へのアラインメント、Mark / Nat 担当）と PR #194（Edmund 由来の ISO fixes、Hodari 担当）の **closure 提案**、Issue #1390（document type 未定義、Axel / Mark）／ Issue #1339（OIDC4IDA プロファイル作成）を継続論点として扱う構成
- **3 月 13 日コール**: 当月最大の節目。アジェンダ冒頭で「3 仕様の WG Final Call を提案」「Authority Draft の PR #196（Edmund 由来 ISO fixes、Hodari）」「Profiles and Registries（Issue #1390 / Issue #1339）」「CAMARA presentation（Mark / Kosuke / Bjorn）」を扱い、**WG Final Call はコンセンサスで合意成立**。Mark が直後の 19:42 UTC に「The proposed final call was agreed by consensus at the WG call today」と ML 報告し、Gail Hodges が 20:53 UTC に「Great news! A big milestone for the WG」と返信
- **3 月 20 日コール**: Final Call 合意を受けた最初のコール。新規 PR として **PR #197**（authority intro の typo、Hodari）／ **PR #198**（Attachments の ISO fixes、Edmund 由来、Hodari）／ **PR #199**（Issue #1391 対応、Hodari）が登場。Attachments と Schema をトップレベル節として独立扱いに移行
- **3 月 22 日 ML 提起**: Mark Haine が「IDA Final review」スレッドを起動。3/27 コールで **OIDF 全体投票へ提案を進めるための WG 同意（クォーラム要件付き）** を諮ると予告し、WG メンバーに出席を強く要請
- **3 月 27 日コール**: クォーラム要件を満たした上での WG コンセンサス確認会。新規 PR として **PR #202**（Issue #1398 = 重複見出し対応、identity-assurance）／ **PR #203**（copyright year を 2024 に更新）／ **PR #201**（schema 修正）が登場し、Final Call 対応の editorial 修正サイクルが本格化

CAMARA プロジェクトとの連携面では、Kosuke Koiwai が 3/3 ML 投稿（[000813](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240226/000813.html)）で **CAMARA KnowYourCustomer サブプロジェクトの 3/19 会合への OpenID 側プレゼン枠** を提案。3/6 投稿（[000814](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240304/000814.html)）で Toshi（KYC SP 議長）が当該会合への招待を確定する旨を共有した。プレゼン対象は「**Attribute Source Claims (ASC) による Age Verification 手法**」であり、ConnectID の静的 claims 方式と、変換 claims（ASC）方式の 2 アプローチを比較する内容。プライバシー上の論点（多数のリクエスト累積で実年齢が漏洩しうる）、国境を越えた閾値年齢の選定、タイムゾーン端境などが議題となる予定として共有された。Daniel Fett も参加を表明（ただし 3 月第 2 週以降を希望）。3/13 コールのアジェンダにも「Advanced Syntax — CAMARA presentation」項目が含まれており、3/19 の CAMARA 会合プレゼンに向けた WG 内事前調整が行われたとみられる。

共同議長体制は当月時点で **Mark Haine / Naohiro Fujie / Torsten Lodderstedt / Tony Nadalin の 4 名体制**（Hodari McClain の共同議長就任は同年 12 月）。Mark Haine が毎週水曜の WG コール用アジェンダを ML に配信し、WG 運営の実質的なドライバーを務めていた。

ML 投稿数は **11 通**。内訳は:

- WG 定例コール用アジェンダ 4 通（3/6・3/13・3/20・3/27）
- WG コール後の Final Call 合意報告 + 返信 2 通（3/13、Mark / Gail Hodges）
- ASC × CAMARA Age Verification スレッド 3 通（2/29 開始、3/3・3/6 と 3/21 に Sunpreet Arora が再話、計 3 通が 3 月期間内）
- カレンダー更新通知 1 通（3/6、Mike Leszcz）
- 「IDA Final review」呼びかけ 1 通（3/22、Mark）

返信付きのスレッドは「ASC to CAMARA」（複数週にまたがる）と「Agenda 13-03-2024」（Mark の Final Call 合意報告 + Gail Hodges の返信）の 2 本。後者は単なるアジェンダ通知ではなく **WG にとっての歴史的節目** にあたる。

eKYC-IDA WG の正式リポジトリは [bitbucket.org/openid/ekyc-ida](https://bitbucket.org/openid/ekyc-ida) であり、GitHub 上の `openid/ekyc-ida` は当月時点で公開リポジトリとして存在しない（404）。Bitbucket Cloud は SPA レンダリングのため WebFetch では Issue / Wiki / PR 本文を取得できない構造的制約があり、本稿は **ML pipermail 公開アーカイブの 3 月期投稿 11 通** を一次情報の中核に据えて再構成している。議事録は WG ポリシーにより non-public で、ML アジェンダおよび Mark Haine の事後報告メールから内容を間接再構成する。

## 2. 公開された仕様・ドラフト改訂

### 2.1 当月の位置付け — 3 仕様の WG Final Call が正式起動

2024 年 3 月期間中の openid.net 上のドラフト本体への新規版番号公開アナウンスは確認できない。**openid.net 上の公式 Public Review ドラフト URL は同年 7 月 24 日の 60 日 Public Review 起動と同日に初公開** されたため、3 月時点では openid.net 上の Public Review 版は存在せず、WG 内編集（Bitbucket エディタブランチ上）の段階にとどまる。

しかし当月の本質は版番号公開ではなく、**3/13 コールにおける「3 仕様の WG Final Call 開始」コンセンサス成立** である。これは OIDF の Final Specification 採択プロセス（WG Final Call → Public Review → Notice of Vote → OIDF 全体投票）の **最初の正式ステップ** にあたり、その後の 60 日 Public Review 起動（7/24）／ Notice of Vote（9/16 早期投票開始、9/23-9/30 本投票）／ 9/30 投票結果公表（賛成 89 / 反対 0 / 棄権 18 で 3 仕様 Final 採択）へとつながる長い経路の **起点** が当月にあった。

Final Call 対象 3 仕様の正式タイトル（3/13 アジェンダおよび 3/22「IDA Final review」メールから抽出）:

1. **`openid-ida-verified-claims`** （OpenID IDA Verified Claims、後の OpenID Identity Assurance Schema Definition 1.0 に対応）
2. **`openid-connect-4-identity-assurance`** （OpenID Connect for Identity Assurance 1.0）
3. **`openid-connect-4-ida-claims`** （OpenID Connect for Identity Assurance Claims Registration 1.0）

### 2.3 「IDA Final review」呼びかけ — クォーラム要件付きの WG 同意手続き

Mark Haine が 3/22 13:28 UTC に [000822](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240318/000822.html) で「IDA Final review」スレッドを起動した。内容は次のとおり:

- 3 仕様（`openid-ida-verified-claims` / `openid-connect-4-identity-assurance` / `openid-connect-4-ida-claims`）が **Final review フェーズ** にある
- 3/27 の WG コールにおいて **OIDF 全体投票へ提案を進めるための WG 同意** を諮る
- 当該決定には **クォーラム（quorum）が要件** となる
- WG メンバーに出席を強く要請。対面参加が「最も簡便」

このメールは、3/13 にコンセンサスで成立した「WG Final Call 開始」とは別の手続きステップを示す。OIDF の Final Specification 採択プロセスでは、WG Final Call の後に「Public Review への移行」「Notice of Vote」「Foundation-wide 投票」と続くが、その各段階で WG 合意を確認する必要がある。3/27 コールで諮られた合意は、後の 7/24 Public Review 起動／ 9/23-9/30 Foundation 全体投票へ至る経路の **最初の関門** にあたる。

### 4.1 [Present ASC to CAMARA Age Verification use case](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240226/000813.html) — 2024 年 3 月 3 日 開始（Kosuke Koiwai）

OpenID eKYC-IDA WG の Age Verification 手法（とくに **Attribute Source Claims (ASC)**）を CAMARA プロジェクトの KnowYourCustomer サブプロジェクトへプレゼンする調整スレッド。スレッド構成と発言者:

- **000813** Kosuke Koiwai 3/3: 3/5 開催予定の CAMARA KnowYourCustomer サブプロジェクト会議への OpenID 側プレゼン枠を提案。プレゼン対象は **(a) 静的 claims 方式（ConnectID 由来）**と **(b) 変換 claims 方式（ASC、実装可能性と preset alias 含む）** の 2 アプローチの比較。論点として「プライバシー（多数のリクエスト累積で実年齢に収束する問題）」「国境を越えた閾値年齢の選定」「タイムゾーン端境」を提示。Daniel Fett の参加意思（ただし 3 月第 2 週以降を希望）と、Toshi（KYC SP 議長）によるスケジューリング担当を共有
- **000814** Kosuke Koiwai 3/6 03:38 UTC: Toshi が **3/19 開催の CAMARA KnowYourCustomer サブプロジェクト会合** への招待を確定したことを共有。プレゼン素材には ISO18013-5 の `age_over_NN` claims や、過去の世界的な age 標準化試みからの教訓も含める方向で議論
- **000821** Sunpreet Arora（Visa）3/21 17:18 UTC: 不在で応答が遅れた旨を述べ、Age Verification use case と OpenID 側の関連既存活動について **「ポインタや提案を共有してほしい」と要請**。本人が CAMARA プレゼン直後にようやくキャッチアップしたことを示す投稿

このスレッドの帰結は当月 ML 上では確定していない。3/19 の CAMARA 会合自体の議事は OpenID 側 ML には投稿されておらず、3/20 コールの External Organizations セクションでの口頭報告で扱われたとみられる。**この CAMARA × Age Verification 連携は 4 月の「Move transaction specific purpose out of the main specification」スレッド（Axel Nennker 発端、4/22-25、6 通往復）の伏線にあたる** 文脈を形成しており、CAMARA プロジェクトと OIDF eKYC-IDA / DPC WG をまたぐ横断議論の初期段階として記録される。

## 5. GitHub 上の議論

eKYC-IDA WG は **GitHub 上にメイン仕様リポジトリを保有していない**。レジストリ上は `https://github.com/openid/ekyc-ida` が記載されているが、2024 年 3 月時点では当該パスは 404 を返し、独立した有意な GitHub 活動はない。WG のメイン作業は [bitbucket.org/openid/ekyc-ida](https://bitbucket.org/openid/ekyc-ida) で行われている。後の 2026 年に立ち上がることになる補助リポジトリ（`openid/eKYC-IDA-Authority` ／ `openid/eKYC-IDA-Registry-Profile`）は 2024 年 3 月時点では存在しない。
