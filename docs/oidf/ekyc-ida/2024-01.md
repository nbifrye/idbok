# OpenID Foundation eKYC-IDA WG 活動レポート (2024年1月)

> 執筆日: 2026-05-22（遡及執筆）
>
> 本記事は 2024 年 1 月の活動を 2026-05-22 時点の視点で遡及的にまとめたものです。

## 1. 概要

eKYC & Identity Assurance Working Group（以下「eKYC-IDA WG」）は、本人確認済みクレーム（verified claims）と検証プロセスのメタデータを OpenID Connect 上で標準的に伝達する仕組みを策定する OpenID Foundation の WG である。中核仕様は **OpenID Connect for Identity Assurance 1.0 (OIDC4IDA)**、**OpenID Identity Assurance Schema Definition 1.0**、**OpenID Connect for Identity Assurance Claims Registration 1.0** の 3 本。

**2024 年 1 月は、3 月 13 日コールで成立することになる「3 仕様の WG Final Call 提案」コンセンサスへ向けた助走期の入口にあたる月** である。当月期間中の WG 定例コール（毎週水曜 UTC 15:00 開催想定）は、1/10 と 1/17 の 2 回が開催され、1/24 はキャンセル、月末 1/31 が再開、という変則的な進行となった。1/10 コールは前年 12 月 20 日のアジェンダを引き続き扱う形となっており（年明け最初の実質討議）、1/17 アジェンダで初めて「Move to final for OpenID Connect for Identity Assurance」が冒頭主議題として明示的に登場、1/31 アジェンダでもそれが継承された。すなわち **「Move to final」主議題化のスタート地点は 1/17 コール** であり、これは翌 2 月期の 4 回のコール（2/7・2/14・2/21・2/28）がすべて同じテーマを継承し、3/13 の Final Call コンセンサス成立へと進む流れの起点に位置する。

当月期間中に確認できる ML 投稿は **9 通**（参考: 1/10 アジェンダは前年 12/20 アジェンダ題名を踏襲した題名で年明け配信。1/3 の理事選挙告知と 1/4 の OSW2024 告知は WG 直接議題ではないが当月期間中の投稿）。技術議論は基本的に WG コール内に集中し、ML 上は事務的なアジェンダ通知中心という、後の 2 月期と同様の運用パターンが当月既に確立されている。

当月の流れを整理すると次のとおり:

- **1 月 3 日**: Mike Leszcz が「2024 OpenID Foundation Board Elections」開票開始を ML 周知（投票期限 1/16 12:00 PST）。コミュニティ枠は George Fletcher / Michael B. - **1 月 10 日コール**: 年明け最初の WG コール。Mark Haine がアジェンダ題名を「20-12-2023」のまま配信（年末年始休止明けで前回 12/20 のアジェンダ題名を踏襲）。Issue #1365（document restructuring）／ Issue #1388（JSON schema 更新）／ `txn` usage clarification 系 PR 群／ Issue #1363（ISO 構造アラインメント、Mark / Nat 担当）／ Advanced Syntax for Claims の Issue #1382（Terminology 節、Daniel 担当）／ Client Registration Metadata 議題（Dima 担当）を扱う構成。Bjorn Hjelm が同日アジェンダへの返信で「External Organizations に CAMARA project 関連の議題を追加したい」と提案

このように 1 月期は、(1) 年明け最初のコール（1/10）が前年 12/20 アジェンダの継承から始まり、(2) 1/17 コールで「Move to final」主議題化が新規確立、(3) 1/24 が予定変更でキャンセル、(4) 1/31 で Issue #1380 を closure 扱いするなど、Final 化へ向けた編集論点の整理が緩やかに進む段階にあった。Issue #1363（ISO 構造）／ Issue #1388（schema 更新）／ Issue #1382（Advanced Syntax Terminology）の 3 つは当月の 2 回のコール（1/17・1/31）と次月以降の主要論点として継承される。**PR #194（後の「Edmund 由来 ISO fixes」と呼ばれることになる ISO 関連 fixes）が 1/31 アジェンダで初登場** している点も、2 月期に Hodari リードへ引き継がれていく前段として注目に値する。

共同議長体制は当月時点で **Mark Haine / Naohiro Fujie / Torsten Lodderstedt / Tony Nadalin** の 4 名体制（Hodari McClain の共同議長就任は同年 12 月）。Mark Haine が WG コール用アジェンダの配信と月次運営の実質的なドライバーを務めていた。

eKYC-IDA WG の正式リポジトリは [bitbucket.org/openid/ekyc-ida](https://bitbucket.org/openid/ekyc-ida) であり、GitHub 上の `openid/ekyc-ida` は当月時点で公開リポジトリとして存在しない（404）。Bitbucket Cloud は SPA レンダリングのため WebFetch では Issue / Wiki / PR 本文を取得できない構造的制約があり、本稿は **ML pipermail 公開アーカイブの 1 月期投稿 9 通（うち WG 議題関連 7 通）** を一次情報の中核に据えて再構成している。議事録は WG ポリシーにより non-public で、ML アジェンダおよび Naohiro Fujie の応答メールから内容を間接再構成する。

## 2. 公開された仕様・ドラフト改訂

### 2.1 当月の位置付け — Final Call 助走期の入口

2024 年 1 月期間中の openid.net 上のドラフト本体への新規版番号公開アナウンスは確認できない。openid.net 上の公式 Public Review ドラフト URL は同年 7 月 24 日の 60 日 Public Review 起動と同日に初公開されたため、1 月時点では openid.net 上の Public Review 版は存在せず、WG 内編集（Bitbucket エディタブランチ上）の段階にとどまる。さらに 3 月 13 日コールで成立することになる「3 仕様の WG Final Call 提案」コンセンサスもまだ未到達であり、当月は **Final Call を諮るための編集懸案の棚卸しが本格化する直前の助走期** に位置する。

Final Call 対象 3 仕様の正式タイトル（後の 3/13 アジェンダから抽出される名称）:

1. **`openid-ida-verified-claims`** （OpenID IDA Verified Claims、後の OpenID Identity Assurance Schema Definition 1.0 に対応）
2. **`openid-connect-4-identity-assurance`** （OpenID Connect for Identity Assurance 1.0）
3. **`openid-connect-4-ida-claims`** （OpenID Connect for Identity Assurance Claims Registration 1.0）

### 2.3 Advanced Syntax for Claims — Issue #1382（Terminology 節）

1/10 アジェンダおよび 1/17 アジェンダの両方で「Advanced Syntax for Claims」セクションが独立して存在し、Issue #1382「complete the Terminology section」が継続論点として扱われた。担当者として **Daniel** が明示されている（Daniel Fett の可能性が高いが ML 投稿では first name のみ）。Advanced Syntax for Claims は OIDC4IDA 中核仕様とは別ドキュメントとして編集が進められていた仕様で、後の WG 議論では ASC（Attribute Source Claims）として参照される文脈と接続する。

### 2.4 Client Registration Metadata 議題（1/10 アジェンダ AOB）

1/10 アジェンダの AOB 節に「Client Registration Metadata」が **Dima** 担当で記載されている。これは OIDC4IDA の Final 化対象外の周辺論点として WG コール内で扱われたものとみられる。Dima（Dima Postnikov / オーストラリアの ConnectID 関係者と推定）は後の 2/14 アジェンダで「ConnectID Use Cases Presentation」を担当することになる人物と同一人物の可能性が高いが、ML 投稿本文では first name のみ言及のため厳密確定は議事録（non-public）の確認を要する。

### 2.5 日本政府 GBizID 関連議題（1/17 アジェンダ Authority Draft）

1/17 アジェンダの Authority Draft 節で **日本政府の GBizID 関連の議論** が項目化されている。GBizID は日本政府が運営する法人向け共通認証サービスで、後の 1/31 ML 投稿で Naohiro Fujie が報告する「digital agency が legal entity 向け ID 基盤に OIDC4IDA を組み込む方向の議論」と直接接続する文脈にあたる。OpenID Summit Tokyo 2024（1/19 開催）の前週コール（1/17）に既に GBizID 議題が登場している点は、サミットを契機とした日本側との接触準備が WG コール内で進められていたことを示す。

## 5. GitHub 上の議論

eKYC-IDA WG は **GitHub 上にメイン仕様リポジトリを保有していない**。レジストリ上は `https://github.com/openid/ekyc-ida` が記載されているが、2024 年 1 月時点では当該パスは 404 を返し、独立した有意な GitHub 活動はない。WG のメイン作業は [bitbucket.org/openid/ekyc-ida](https://bitbucket.org/openid/ekyc-ida) で行われている。後の 2026 年に立ち上がることになる補助リポジトリ（`openid/eKYC-IDA-Authority` ／ `openid/eKYC-IDA-Registry-Profile`）は 2024 年 1 月時点では存在しない。

Bitbucket Cloud は SPA（JavaScript レンダリング）で HTML を生成するため、WebFetch 経由では Issue / Wiki / Pull Request の本文を取得できない構造的制約がある。本稿では §2・§3・§4 で示したとおり、**ML 上のアジェンダメール（1/10・1/17・1/31 の 3 通）に列挙された Issue / PR 番号と短い説明文** を一次情報として再構成し、Bitbucket 直接アクセスを伴わない範囲で WG の議論内容を表現している。

1 月期間中の Bitbucket 側 PR / Issue 動向（ML アジェンダから抽出）の主要群:

- **Identity Assurance（中核仕様）— Final 化準備の編集論点**:
  - **Issue #1363**（`Consider aligning to ISO structure`、Mark / Nat 担当）: 1/10・1/17・1/31 アジェンダで継続論点。当月後半は PR #192（errors fixes）と PR #194（ISO fixes、1/31 初登場）が並列で付随。2 月期に Hodari リード PR #194 へ引き継がれ、2/28 で closure 提案へ昇格
  - **PR #192**（Issue #1363 関連の errors fixes、Mark / Nat 担当）: 1/17 アジェンダで初出。1/31 でも継続
  - **PR #194**（ISO fixes、後の「Edmund 由来 ISO fixes」）: 1/31 アジェンダで初登場。2 月期に Hodari リードへ
- **Identity Assurance — Schema 周りの編集**:
  - **Issue #1388**（JSON schema 更新）: 1/10・1/17・1/31 アジェンダで継続論点
  - **PR #193**（schema test failure cases、Mark プレゼン）: 1/17 アジェンダで初出。1/31 でも継続。2 月期・3 月期・4 月期にわたるロングラン論点
- **Identity Assurance — Restructuring**:
  - **Issue #1365**（document restructuring）: 1/10・1/17 アジェンダで継続論点。1/31 では明示的言及なし
- **Identity Assurance — Closure 扱い**:
  - **Issue #1380**（`consent and error handling contradiction`）: 1/31 アジェンダで **closure 扱い**。当月唯一の closure アクション
- **Advanced Syntax for Claims**:
  - **Issue #1382**（Terminology 節の完成、Daniel 担当）: 1/10・1/17・1/31 アジェンダで継続論点。後の CAMARA × ASC プレゼン議論（2/21 ML 投稿）で「ASC's approach」として参照される文脈と接続

  - 1/10 アジェンダで言及。PR 番号は ML 投稿本文では具体的に明示されていないが、`txn`（トランザクション ID）の使用法明確化に関する複数 PR が継続検討中

**1 月期の WG 活動の本質は、(1) 年明け再開コール（1/10）で前年からの編集論点を継承し、(2) 1/17 コールで「Move to final」主議題化を新規確立しつつ CAMARA ミーティング報告と日本政府 GBizID 議論を Authority Draft 節で議題化し、(3) 1/24 キャンセルを挟んで、(4) 1/31 コールで Issue #1380 を closure 扱いとし PR #194 を初登場させた** ことに集約される。Final 化対象 3 仕様の編集論点棚卸しの本格化は 2 月期 4 回のコールに引き継がれ、3/13 コールでの WG Final Call 提案コンセンサス成立へと進む流れの起点が当月にある。
