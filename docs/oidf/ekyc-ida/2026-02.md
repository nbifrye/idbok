# OpenID Foundation eKYC & IDA WG 活動レポート (2026年2月)

> **執筆日**: 2026-04-17（遡及執筆）
>
> 本記事は 2026年2月の活動を 2026-04-17 時点の視点で遡及的にまとめたものです。

## 1. 概要

**eKYC & Identity Assurance WG (eKYC-IDA WG)** は、OpenID Connect を拡張して本人確認済みクレームの標準的な伝達方法を定義する Working Group である。WG 議長は Mark Haine、Naohiro Fujie、Hodari McClain。毎週水曜 15:00 UTC に定例コールを開催し、成果物のホスティングには Bitbucket (https://bitbucket.org/openid/ekyc-ida) を利用している。

2026年2月は、3月以降の大きなマイルストーンに向けた準備が集中した月である。主要な動きとして、**OpenID Connect Advanced Syntax for Claims (ASC) 1.0** の初 Implementer's Draft（ID1）への推薦に向けた最終調整、**OpenID Connect for Identity Assurance 1.0** 正誤表（Errata Set 1）の会員レビュー提案、**mDL（mobile Driver's License）プロファイル**の方針転換、そして **Authority サブグループ**の設立準備が進められた。メーリングリストには週別アーカイブが存在し、各週の議題メールおよびスレッドから WG の活動を再構成できた。

## 2. 公開された仕様・ドラフト改訂

2026年2月には、公開仕様や Implementer's Draft の正式公開は行われなかった。ただし以下の 2 件について、2月中に会員レビューへの提案が行われた。

### 2-1. OpenID Connect Advanced Syntax for Claims (ASC) 1.0 — ID1 推薦に向けた最終調整

**OpenID Connect Advanced Syntax for Claims (ASC) 1.0** は、OpenID Connect を拡張してクレームの要求・受領における高度なデータ最小化を実現する仕様である。著者は Daniel Fett（Authlete）。仕様は以下の2コンポーネントで構成される。

- **Selective Abort and Omit (SAO)**: RP が特定クレームの不在時やユーザー非同意時における OP の挙動（中断または省略）を事前に指定できる機能
- **Transformed Claims (TC)**: クレーム値に変換関数チェーンを適用した結果を返す機能。典型例は生年月日を「18歳以上か否か」のブール値へ変換する年齢確認ユースケース

2月4日の議題メールでは「2月11日のコールで ID1 として提案するかどうかを決定する」とされており、2月11日の議題では「ASC を ID1 として会員レビューおよび投票のために提案する」として進んでいることが確認できる。2月25日の議題では「ID1 公開の事務処理（Mark & Hodari 担当）」が残タスクとして明示された。

この一連の事務処理完了を経て、ASC 1.0 は 2026-03-06 に Draft -01 として公開され、翌 2026-03-16 に公開レビュー期間が開始された。

### 2-2. OpenID Connect for Identity Assurance 1.0 — Errata Set 1 会員レビュー提案

**OpenID Connect for Identity Assurance 1.0**（および **OpenID Identity Assurance Schema Definition 1.0**）の Errata Set 1 については、2月4日の議題で「Issue #1501（住所の例示）についてはロールバックせず、2月11日のコールまでに会員レビュー用の正誤表提案を目指す」と方針が示された。2月11日の議題では正式に「会員レビューのために Errata を提案する」として次フェーズへ進んだ。

この会員レビュー提案を経て、正誤表のパブリックレビューは 2026-03-30 にアナウンスされた（その後 2026-04-01 に両仕様の合同パブリックレビューとして更新）。

## 4. メーリングリストの主要スレッド

メーリングリスト（`openid-specs-ekyc-ida@lists.openid.net`）の 2026年2月アーカイブは週別形式で公開されており、以下のスレッドが確認された。

### [eKYC and IDA WG Agenda 04-02-2026](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20260202/001002.html) — 2026-02-04 開始

Mark Haine による週次議題メール。Identity Assurance Errata の Issue #1501 に対する方針（住所フォーマットを追加しない）、ASC ID1 提案の決定期限（2月11日）、および新サブグループ設立に関する議論の案内が含まれる。

### [Informal Subgroup: Identity Assurance Schema](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20260202/001003.html) — 2026-02-04 開始

Gail Hodges（OIDF）が Identity Assurance Schema インフォーマルサブグループのスコープ草案を共有したスレッド（全 2 通、Juliana Cafik が返信）。

Gail によれば、このイニシアティブは NIST の「mDL を使って銀行口座を開設するユースケース」から始まったギャップ分析に基づくもの。OIDF 理事会が委託したレポートが米国・オーストラリア・ニュージーランド・EU にわたる要件を調査しており、ISO/IEC SC17 WG10 が翌週に会合を予定していることから、NIST が本作業を参照しており IP 保護の観点でも早急な対応が必要だと訴えた。Juliana Cafik と Mark Verstege が WG との窓口（リエゾン）を担うと表明した。

Juliana の返信では、自身が eKYC & mDL 向けの mDL メタデータプロファイル草案を作成し、WG の work item として提案していることが明かされた。この流れは 2月10日のスレッドで大きく展開する。

### [Working Group Draft mDL Profile for OIDC4IDA](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20260209/001007.html) — 2026-02-10 開始

Mark Haine が送付した、**mDL プロファイルの方針転換を告知する重要スレッド**。

Juliana と Mark の協議の結果、既存の mDL プロファイル草案を取り下げ、新たな方向性として以下を提案した：

> 金融サービス向け mDL プロファイルを、OpenID for IDA スキーマと OpenID Attachments を活用して開発し、支援レジストリを合わせて整備する

元の草案は verified claims コンテナ・義務的な検証メタデータ・準拠性フレームワーク（出所証明・保有者バインディング・失効確認）・JSON ペイロード例などを含む技術的な内容だったが、こちらは廃棄される。新アプローチへの共同編集者を募集中とした。

この方針転換は 2月11日の議題に即座に反映され、Profiles & Registries 項目として「金融サービス向け mDL プロファイルの開発提案」が掲げられた。

### [Lastest eKYC Certification tests](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20260202/001005.html) — 2026-02-05

Edmund Jay（conformance testing 担当）が eKYC 適合性テストスイートの改善を告知したメール。

改善内容：従来の認証テストでは ID Token と Userinfo の両方から verified identity claims を取得する必要があったが、新版ではクレームを取得するエンドポイントを設定可能にした。テスト側が ID Token のみ・Userinfo のみ・両方から取得する3パターンに対応するようになり、より多様なアーキテクチャの実装を受け入れられるようになった。プレビュー版がステージングサーバー（`https://staging.certification.openid.net`）で確認可能との案内あり。

### [Request for Reviewers: Age Assurance & Child Protection whitepaper](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20260202/001006.html) — 2026-02-06

Gail Hodges が Age Assurance & Child Protection ホワイトペーパーの専門家レビューを WG に依頼したメール。

OIDF 理事会が 2025年4月に開発を承認した本ホワイトペーパーは、Rachel O'Connell（編集長）と Elizabeth Garber（エディター）が担当。複数の法域にわたるポリシー・技術面のランドスケープアセスメントを含む。パブリックコメント前の初稿レビューとして、7〜10日以内に草案を配布予定とした。eKYC & IDA の専門家としてのフィードバックが特に期待されているとして、Gail は参加希望者に連絡を求めた。

また、2月中に **Authority** および **Profiles & Registries** の新 GitHub リポジトリが設立された。2月25日の議題では「新 GitHub リポジトリが設立された」と明記されており、これらの作業が本格始動したことがわかる。

## 6. 関連イベント

### TIIME 2026 (Trust and Internet Identity Meeting Europe)（2026-02-09〜02-13、アムステルダム）

TIIME 2026 が 2026年2月9〜13日にアムステルダム（Nikhef）で開催された。メインのアンカンファレンスは 11〜12 日、OpenID Federation ワークショップは 13 日に開催された。

OpenID Federation の相互接続性テストイベントでは、9か国・9実装・12名の参加者が相互テストを実施し、高い相互運用性を実証した（この結果は 2026-02-18 に OIDF から公式発表）。eKYC-IDA WG 固有のセッションの開催は確認できなかったが、2月11日の議題メールでは「外部組織とイベントの簡単なレビュー」として TIIME 2026 が OIDF Google カレンダーに登録されていることが示されており、WG メンバーがイベントを認識・参照していたことがわかる。

### OpenID Foundation 自己認証プログラム開始（2026-02-26）

OpenID Foundation は 2026年2月26日から、OpenID for Verifiable Presentations (OID4VP) 1.0、OpenID for Verifiable Credential Issuance (OID4VCI) 1.0、High Assurance Interoperability Profile (HAIP) 1.0 の自己認証プログラムを開始した。eKYC-IDA WG が管理する OIDCv4IDA 仕様の認証プログラムとは別物だが、同 WG が開発した仕様と連携するデジタルクレデンシャルエコシステム全体の成熟を示す動きであり、WG の議論でも参照された。
