# OpenID Foundation eKYC-IDA WG 活動レポート (2024年2月)

> 執筆日: 2026-05-22（遡及執筆）
>
> 本記事は 2024 年 2 月の活動を 2026-05-22 時点の視点で遡及的にまとめたものです。

## 1. 概要

eKYC & Identity Assurance Working Group（以下「eKYC-IDA WG」）は、本人確認済みクレーム（verified claims）と検証プロセスのメタデータを OpenID Connect 上で標準的に伝達する仕組みを策定する OpenID Foundation の WG である。中核仕様は **OpenID Connect for Identity Assurance 1.0 (OIDC4IDA)**、**OpenID Identity Assurance Schema Definition 1.0**、**OpenID Connect for Identity Assurance Claims Registration 1.0** の 3 本。

**2024 年 2 月は、翌 3 月 13 日の WG コールで成立する「3 仕様の WG Final Call 提案」コンセンサスへ向けた地ならしの月** にあたる。1 月末（1/31 コール）の時点で既に「**Move to final for OpenID Connect for Identity Assurance**」がアジェンダの中心議題となっており、2 月期の 4 回の WG コール（2/7・2/14・2/21・2/28）はすべて同じテーマを冒頭主議題として継承した。ISO 構造アラインメント（Issue #1363）と Edmund 由来 ISO fixes（PR #194）、JSON schema 周りの更新（Issue #1388・PR #193）、document type 定義欠落（Issue #1390）、OIDC4IDA プロファイル作成（Issue #1339）といった Final Call 直前期の編集論点が一通り出揃い、月末 2/28 アジェンダでは Issue #1363 と PR #194 が **closure 提案** として明示的に扱われるところまで進んだ。この closure 提案構造はそのまま 3/6 アジェンダに引き継がれ、3/13 の Final Call コンセンサス成立の前段準備として機能した。

当月の流れを整理すると次のとおり:

- **2 月 7 日コール**: 当月最初の定例。「Move to final for OpenID Connect for Identity Assurance」を主議題に据え、Issue #1363（ISO 構造）／ PR #194（Edmund 由来 ISO fixes）／ Issue #1388（JSON schema 更新）／ PR #193（schema test failure cases）／ Issue #1382（Advanced Syntax の Terminology 節）を扱う構成
- **2 月 14 日コール**: Final 化主議題の継続。ConnectID use case プレゼン（Dima 担当）が新規セクションとして追加。Identity Assurance 側は ISO 構造アラインメントの引き続き検討と、`ida-verified-claims` 用語の参照修正、schema 更新の進捗確認
- **2 月 21 日コール**: Final 化主議題の継続。Issue #1390（document type 未定義、Axel / Mark）と Issue #1339（OIDC4IDA プロファイル作成）が初めて明示的にアジェンダ項目化。Issue #1363（ISO 構造）に PR #194（Hodari リード）が付随する形は前週 2/14 アジェンダから継続。schema test failure cases（PR #193）も継続
- **2 月 21 日 ML 提起**: Kosuke Koiwai が「**Present ASC to CAMARA Age Verification use case**」スレッド（[000811](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240219/000811.html)）を起動。CAMARA KnowYourCustomer サブプロジェクトへの OpenID 側プレゼン枠（当初 3/5 を提案）と、ASC（Attribute Source Claims）方式と ConnectID 静的 claims 方式の比較というプレゼン素材構成を提示。Daniel に 2/28 コール出席の可否を打診（ML 投稿本文では first name のみ言及）
- **2 月 28 日コール**: 月末コール。**Issue #1363 と PR #194 を closure 提案として明示**。Issue #1390 と Issue #1339 を継続論点。CAMARA × ASC プレゼン議論は同コール内では公式アジェンダ化されず、ML スレッド側で継続

3 月期で確立される「アジェンダ構造テンプレート」の原型は当月にはまだ存在せず、2 月期のアジェンダは「**Identity Assurance（Move to final）+ Advanced Syntax for Claims**」の 2 セクション基本構成にとどまる。Attachments / Schema / Authority がそれぞれ独立トップレベル節へ昇格するのは 3/20 コール以降の話であり、当月時点ではこれらは Identity Assurance セクション内のサブ論点として扱われていた。

CAMARA プロジェクトとの連携は当月後半から ML 上で動き始めた。Kosuke Koiwai の 2/21 投稿は CAMARA 側 (Toshi が KYC SP 議長) との接触初期段階を示すもので、MWC（Mobile World Congress、2/26–2/29 バルセロナ開催）に CAMARA 関係者が多数参加していたことが続報（3/3 投稿）で言及されている。3/19 の CAMARA KnowYourCustomer サブプロジェクト会合への招待確定は翌 3 月期の話であり、2 月期は **CAMARA プレゼン提案の初期接触** にあたる。

共同議長体制は当月時点で **Mark Haine / Naohiro Fujie / Torsten Lodderstedt / Tony Nadalin** の 4 名体制（Hodari McClain の共同議長就任は同年 12 月）。Mark Haine が毎週水曜の WG コール用アジェンダを ML に配信し、WG 運営の実質的なドライバーを務めていた。1/31 のアジェンダ ML（[000806](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240129/000806.html)）への Naohiro Fujie の返信（[000807](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240129/000807.html)）では、**OpenID Summit Tokyo 2024**（2024-01-19 開催）について「over 350 attendees」「25.3% of attendees have interest in implementing OID4IDA」という参加者規模と関心度を報告し、サミット後に Fujie と Mark Haine が **日本のデジタル庁担当者と OIDC4IDA を国の法人向け ID 基盤に組み込む方向で議論した** ことが共有された。この投稿は 2 月期の WG コールにも継続して影響する文脈を 1 月末時点で先行投入した形になっている。

ML 投稿数は当月期間中 **5 通**。内訳は:

- WG 定例コール用アジェンダ 4 通（2/7・2/14・2/21・2/28）
- CAMARA × ASC Age Verification プレゼン提案 1 通（2/21、Kosuke Koiwai 発端）

返信付きのスレッドは当月期間中ゼロ（CAMARA × ASC スレッドへの Kosuke 自身の続報投稿 [000813](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240226/000813.html) は 3/3 14:37 UTC 投稿のため 3 月期に計上）。**4 月期や 3 月期と比較して ML 上の往復は静かな月** だが、これは「Final Call 提案直前の準備期」という性格上、議論が WG コール内に集中し ML には事務的なアジェンダ通知が中心となったためと解釈できる。

eKYC-IDA WG の正式リポジトリは [bitbucket.org/openid/ekyc-ida](https://bitbucket.org/openid/ekyc-ida) であり、GitHub 上の `openid/ekyc-ida` は当月時点で公開リポジトリとして存在しない（404）。Bitbucket Cloud は SPA レンダリングのため WebFetch では Issue / Wiki / PR 本文を取得できない構造的制約があり、本稿は **ML pipermail 公開アーカイブの 2 月期投稿 5 通（および前後文脈のため 1/31 と 3/3 投稿）** を一次情報の中核に据えて再構成している。議事録は WG ポリシーにより non-public で、ML アジェンダおよび Naohiro Fujie の応答メールから内容を間接再構成する。

## 2. 公開された仕様・ドラフト改訂

### 2.1 当月の位置付け — Final Call 提案前夜の編集論点整理

2024 年 2 月期間中の openid.net 上のドラフト本体への新規版番号公開アナウンスは確認できない。**openid.net 上の公式 Public Review ドラフト URL は同年 7 月 24 日の 60 日 Public Review 起動と同日に初公開** されたため、2 月時点では openid.net 上の Public Review 版は存在せず、WG 内編集（Bitbucket エディタブランチ上）の段階にとどまる。さらに 3 月 13 日コールで成立することになる「3 仕様の WG Final Call 提案」コンセンサスもまだ未到達であり、当月は **Final Call を諮るための編集懸案を一通り棚卸しした準備期** に位置する。

OIDF の Final Specification 採択プロセス（WG Final Call → Public Review → Notice of Vote → Foundation 全体投票）の正式起動は 3/13 コール待ちであるが、その地ならしの作業は当月の 4 回の WG コールで着実に進められた。**2/28 アジェンダで Issue #1363 と PR #194 が明示的に closure 提案として扱われた** ことが、Final Call 提案前夜の編集論点整理が一段落したことを示す重要な指標である。

Final Call 対象 3 仕様の正式タイトル（後の 3/13 アジェンダおよび 3/22「IDA Final review」メールから抽出される名称）:

1. **`openid-ida-verified-claims`** （OpenID IDA Verified Claims、後の OpenID Identity Assurance Schema Definition 1.0 に対応）
2. **`openid-connect-4-identity-assurance`** （OpenID Connect for Identity Assurance 1.0）
3. **`openid-connect-4-ida-claims`** （OpenID Connect for Identity Assurance Claims Registration 1.0）

### 2.3 Advanced Syntax for Claims — Issue #1382（Terminology 節）

2/7 アジェンダで「**Advanced Syntax for Claims**」セクションが独立して存在し、Issue #1382「complete the Terminology section」が継続論点として扱われた。Advanced Syntax for Claims は OIDC4IDA 中核仕様とは別ドキュメントとして編集が進められていた仕様であり、後の WG 議論では ASC（Attribute Source Claims）として参照される文脈と接続する。2/21 ML 投稿の CAMARA × Age Verification プレゼン議論で Kosuke Koiwai が言及する「ASC's approach」はこの Advanced Syntax for Claims に由来するもので、**2 月期は ASC の WG 内編集と外部（CAMARA）への発信準備が並行していた** ことが読み取れる。

### 2.4 ConnectID Use Cases Presentation（2/14 アジェンダ）

2/14 アジェンダで初めて明示された「ConnectID Use Cases Presentation」（Dima 担当）は、オーストラリアの ConnectID プログラム（Australian Payments Plus 運営、銀行系の verified claims 連携基盤）が OIDC4IDA を採用する文脈での use case 紹介を WG 内に提供するセッション。2/21 投稿の CAMARA × Age Verification プレゼン提案で Kosuke Koiwai が「static claims (ConnectID method)」と「transformed claims (ASC's approach)」を比較する構図を示したのは、この 2/14 コールでの ConnectID use case プレゼン内容を踏まえている可能性が高い。**当月は ConnectID（オーストラリア）／ ASC（OIDC4IDA Advanced Syntax）／ CAMARA（GSMA / 通信事業者）という 3 つの異なるアプローチが WG の認識地図上に並置される最初の時期** にあたる。

## 5. GitHub 上の議論

eKYC-IDA WG は **GitHub 上にメイン仕様リポジトリを保有していない**。レジストリ上は `https://github.com/openid/ekyc-ida` が記載されているが、2024 年 2 月時点では当該パスは 404 を返し、独立した有意な GitHub 活動はない。WG のメイン作業は [bitbucket.org/openid/ekyc-ida](https://bitbucket.org/openid/ekyc-ida) で行われている。後の 2026 年に立ち上がることになる補助リポジトリ（`openid/eKYC-IDA-Authority` ／ `openid/eKYC-IDA-Registry-Profile`）は 2024 年 2 月時点では存在しない。

Bitbucket Cloud は SPA（JavaScript レンダリング）で HTML を生成するため、WebFetch 経由では Issue / Wiki / Pull Request の本文を取得できない構造的制約がある。本稿では §2・§3・§4 で示したとおり、**ML 上のアジェンダメール（2/7・2/14・2/21・2/28 の 4 通）に列挙された Issue / PR 番号と短い説明文**、および Kosuke Koiwai の CAMARA × ASC 投稿で参照された Issue #1172 リンクを一次情報として再構成し、Bitbucket 直接アクセスを伴わない範囲で WG の議論内容を表現している。
