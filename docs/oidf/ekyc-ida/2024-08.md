# OpenID Foundation eKYC-IDA WG 活動レポート (2024年8月)

> 執筆日: 2026-05-20（遡及執筆）
>
> 本記事は 2024 年 8 月の活動を 2026-05-20 時点の視点で遡及的にまとめたものです。

## 1. 概要

eKYC & Identity Assurance Working Group（以下「eKYC-IDA WG」）は、本人確認済みクレーム（verified claims）と検証プロセスのメタデータを OpenID Connect 上で標準的に伝達する仕組みを策定する OpenID Foundation の WG である。中核仕様は **OpenID Connect for Identity Assurance 1.0 (OIDC4IDA)**、**OpenID Identity Assurance Schema Definition 1.0**、**OpenID Connect for Identity Assurance Claims Registration 1.0** の 3 本。

**2024 年 8 月は eKYC-IDA WG にとって、5 年以上を費やしてきた中核 3 仕様の Final 化に向けた 60 日 Public Review 期間（2024-07-24 開始、2024-09-22 終了）のちょうど中盤に位置する月** である。当月は Public Review 期間中のため、(1) Public Review 開始から 1 週間という早い段階で Mike Leszcz（OIDF Operations Director）が 7/30 に WG ML 上に再アナウンスを投稿、(2) Mark Haine が 8 月内に 4 回（8/7・8/14・8/21・8/28）のコール用アジェンダを ML に配信、(3) Public Review 中に発見された editorial 修正を取り込んだドラフト群（PR #226「updated security considerations」・PR #227「updated heading capitalization」など）が 8 月前半に作成され、Schema Definition と Claims Registration 派生 2 仕様の draft 00 系列に反映、(4) **8 月 29 日に Hodari McClain が Identity Assurance 仕様ファミリーの ISO PAS Submission RFC を WG ML に正式配信** し、Final 化後の ISO/IEC ルートでの国際標準化に向けた長期戦略の起点を打った、という構成で進行した。Final 投票期間（9/23-30）と Final 承認アナウンス（10/3）はまだ 2 か月後の出来事である。

共同議長体制は当月時点で **Mark Haine / Naohiro Fujie / Torsten Lodderstedt / Tony Nadalin の 4 名体制**。Hodari McClain（後の 12 月共同議長就任）は当月時点ではメンバーとしての立場で活動しているが、ISO PAS Submission RFC の WG 内ドライバーとして実質的な仕様運営面のリーダーシップを示し始めた月でもある。

ML 投稿数は **6 通**（公開 pipermail 週次アーカイブの厳密な 8/1-8/31 集計で、7/29 週分 1 通 ＋ 8/5 週・8/12 週・8/19 週・8/26 週それぞれの 1 通および Hodari の 8/29 投稿 1 通の合計）。9 月の 8 通前後、10 月の 10 通前後と比較するとやや少ないが、これは Public Review 期間中の典型的な投稿パターンで、WG 内部議論が Bitbucket Issue / PR トラッカー側に集中し、ML への投稿は週次のアジェンダ配信中心になっていた構図を反映している。

8 月内の ML スレッド構成を整理すると次の 3 群:

- **Public Review 期間中の運営アナウンス**: 7/30 Mike Leszcz の Public Review 再アナウンス（[000858](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240729/000858.html)）。60 日 Public Review が 7/24 に開始したことを WG ML 上で再共有する事務通知
- **毎週水曜の WG コール用アジェンダ配信**: Mark Haine が 8/7（[000860](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240805/000860.html)）・8/14（[000861](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240812/000861.html)）・8/21（[000862](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240819/000862.html)）・8/28（[000863](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240826/000863.html)）の 4 通を ML 配信
- **ISO PAS Submission RFC 起動**: 8/29 Hodari McClain（[000864](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240826/000864.html)）。Identity Assurance 仕様ファミリーの ISO PAS Submission ドラフトを Google Doc で WG 共有し、9 月レビュー期間終了後の ISO 正式提出に向けた WG 内フィードバック収集を起動

技術的論点を伴う ML スレッド（返信付き）は当月内には発生していない。WG コール用アジェンダはいずれも返信のない単発投稿で、ISO PAS Submission RFC も Hodari の単発配信で 8 月内には ML 上での返信は記録されていない。Bitbucket 上の PR / Issue 議論が中心の月であった。

eKYC-IDA WG の正式リポジトリは [bitbucket.org/openid/ekyc-ida](https://bitbucket.org/openid/ekyc-ida) であり、GitHub 上の `openid/ekyc-ida` は当月時点で公開リポジトリとして存在しない（404）。Bitbucket Cloud は SPA レンダリングのため WebFetch では Issue / Wiki / PR 本文を取得できない構造的制約があり、本稿は **ML pipermail 公開アーカイブの 8 月期投稿および openid.net の Public Review 関連アナウンスを一次情報の中核** に据えて再構成している。議事録は WG ポリシーにより non-public で、ML アジェンダから内容を間接再構成する。

## 2. 公開された仕様・ドラフト改訂

### 2.1 Public Review 期間中のドラフト（draft 14 / draft 00 系列）

7 月 24 日に開始した 60 日 Public Review（[Public Review for Proposed Final OIDC for Identity Assurance](https://openid.net/public-review-proposed-final-openid-connect-for-identity-assurance/)）の対象は、開始時点で次の 3 仕様:

- **OpenID Connect for Identity Assurance 1.0 — draft 14**（[openid-connect-4-identity-assurance-1_0-14.html](https://openid.net/specs/openid-connect-4-identity-assurance-1_0-14.html)、2024-07-24 公開）
- **OpenID Connect for Identity Assurance Claims Registration 1.0 — draft 00**（2024-07-24 公開）
- **OpenID Identity Assurance Schema Definition 1.0 — draft 00**（2024-07-24 公開）

これらが 8 月期間中の Public Review レビュー対象である。9 月 9 日の Notice of Vote 公表時点で更新版 draft 15 / draft 01 / draft 01 系列に置き換えられることになるが、8 月時点では draft 14 / draft 00 系列が WG コール内および外部レビュアーの議論対象として参照されていた。

Public Review 期間中の典型的な作業として、レビュアーから寄せられたフィードバックを reviewing → editorial PR としてマージ → 9 月の Notice of Vote 直前に更新版を再公開する流れが想定されており、8 月期間中の Bitbucket 側の PR（後述の #226 / #227 等）はその流れに沿った editorial fix と読める。

### 2.4 8 月 29 日 — Identity Assurance Specification Family ISO PAS Submission RFC

8 月 29 日 16:02 UTC、Hodari McClain が ML 配信した [Identity Assurance Specification Family ISO PAS Submission RFC](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240826/000864.html) は、Final 化後の ISO/IEC 国際標準化に向けた長期戦略の起点投稿。要旨（ML 公開アーカイブから再構成）:

- Identity Assurance 1.0 仕様群向け **ISO PAS（Publicly Available Specification）Submission のドラフトを Google Docs で WG 内共有**
- リンクは「すべての閲覧者に開放」されており、コメント問題があれば Hodari に直接連絡
- 既に **Gail（Gail Hodges、OIDF Executive Director）と Mark Haine から初期フィードバックを取得済み**
- **ISO への事前プレビュー** を予定（正式提出前のテクニカルチェック）
- OIDF として **9 月の Public Review 期間終了後（9/22 以降）に ISO へ正式提出** することを目指す
- WG 内フィードバック締切は **9 月中旬目処**

末尾には Hodari の署名コメント「Chance favors the prepared mind」（パスツール由来の格言）が添えられている。

この投稿は、**Final 化承認（10 月 3 日）→ ISO PAS Submission → ISO/IEC 国際標準化** という 3 段階の長期戦略の WG 内公開キックオフであり、9 月 10 日の Michael Jones / Nat Sakimura 間の Duplicate `Normative References` editorial 議論（ISO Directives 整合の `xml2rfc` プレースホルダ）の文脈上の伏線にもなる。Public Review 期間中の 8 月末という絶妙なタイミングで起動された点に注目したい — Final 化と ISO PAS 提出を 1 か月ずつズラして並行進行させる戦略である。

## 5. GitHub 上の議論

eKYC-IDA WG は **GitHub 上にメイン仕様リポジトリを保有していない**。レジストリ上は `https://github.com/openid/ekyc-ida` が記載されているが、2024 年 8 月時点では当該パスは 404 を返し、独立した有意な GitHub 活動はない。WG のメイン作業は [bitbucket.org/openid/ekyc-ida](https://bitbucket.org/openid/ekyc-ida) で行われている。後の 2026 年に立ち上がることになる補助リポジトリ（`openid/eKYC-IDA-Authority` ／ `openid/eKYC-IDA-Registry-Profile`）は 2024 年 8 月時点では存在しない。

Bitbucket Cloud は SPA（JavaScript レンダリング）で HTML を生成するため、WebFetch 経由では Issue / Wiki / Pull Request の本文を取得できない構造的制約がある。本稿では §2・§3・§4 で示したとおり、**ML 上のアジェンダメール（8/7・8/14・8/21・8/28 の 4 通）に列挙された Issue / PR 番号と短い説明文** を一次情報として再構成し、Bitbucket 直接アクセスを伴わない範囲で WG の議論内容を表現している。

8 月時点で ML から確認できる Bitbucket 側の主要な「動き」は次の 4 群に整理できる:

- **Identity Assurance（中核仕様）— Public Review 対応の editorial 修正サイクル**:

  - **Issue #1425**（Joseph、`Make security considerations slightly less empty`）: 8/7 新規
  - **Issue #1426**（Mark、`editorial items for openid-ida-verified-claims`）: 8/7 新規

  - **PR #229**（Mark、`editorial fix to remove vestigial purpose`）: 8/21 初登場
- **Attachments — 仕様改善**:
  - **PR #220**（editorial 改善）・**PR #221**（claim parameter 改善）: 8/7 アジェンダで言及
  - **Issue #1420**（`Attachments OP Metadata default`）: 8/7・8/14・8/28 で継続
  - **Issue #1428**（Mark、`Add type parameter to attchment draft`）: 8 月全アジェンダで継続
  - **PR #228**（Hodari、`reword OP metadata`）: 8/21 初登場、9 月・10 月・11 月以降の長寿命 PR の起点
