# OpenID Foundation DCP WG 活動レポート (2024 年 4 月)

> 執筆日: 2026-05-21（遡及執筆）
> この記事は 2024 年 4 月の活動を遡及的にまとめたレポートです。

## 1. 概要

Digital Credentials Protocols Working Group（以下「DCP WG」）は、Issuer-Holder-Verifier モデルに基づく検証可能クレデンシャル（W3C VC、IETF SD-JWT VC、ISO/IEC 18013-5 mDL など）の発行・提示・交換に関するプロトコル群を策定する OpenID Foundation の WG である。所掌の主力仕様は **OpenID for Verifiable Credential Issuance (OID4VCI)**、**OpenID for Verifiable Presentations (OID4VP)**、**Self-Issued OpenID Provider v2 (SIOPv2)** の 3 本。2024 年 4 月時点の共同議長は Kristina Yasuda、Joseph Heenan、Torsten Lodderstedt の 3 名体制で、定例コールは「**DCP WG + SIOP call**」名義で APAC 友好枠（火曜 PST midday）と EU 友好枠（木曜 PST 8AM / 5PM CEST）の 2 系統が運用されていた。

2024 年 4 月は DCP WG にとって、**「OID4VCI 1.0 第 1 次 Implementer's Draft (ID1) が 4/1 に OpenID Foundation 投票で承認され、続けて『AB/Connect WG から DCP WG への所管移管』を確定させるための Call for Adoption が 4/15 に発出された月」** にあたる。OID4VCI は 2023 年 8 月の DCP WG 発足以前から AB/Connect WG 配下の SIOP/DCP サブグループの成果物として開発されてきた経緯があり、ID1 承認のタイミングで IPR 保護を確定させたうえで正式に DCP WG の所管文書として採択する手順が踏まれた。openid.net の公式アナウンスがなお「a product of the OpenID Connect Working group」と書く一方で、WG ML 上では「now the specification has moved to Implementer's Draft 1 (and the IPR protections locked in) we need to do a 'call for adoption' to move it to the Digital Credentials Protocols working group」（[#000259](https://lists.openid.net/pipermail/openid-specs-digital-credentials-protocols/Week-of-Mon-20240415/000259.html)、Joseph Heenan、2024-04-15）と移管の文脈が明示された月であった。

本月の主軸テーマは大きく次の 5 系統である。

- **OID4VCI 1.0 ID1 の OIDF 投票承認（4/1）**: 賛成 79 / 反対 2 / 棄権 12 で可決、総投票 93 票が会員 321 名中 29% で 20% クォーラム充足。Marie Jordan による正式アナウンスが ML [#000244](https://lists.openid.net/pipermail/openid-specs-digital-credentials-protocols/Week-of-Mon-20240401/000244.html)（4/1）で投稿された
- **OID4VCI の所管 DCP 移管 Call for Adoption（4/15〜）**: Joseph Heenan が ID1 承認後の手続きとして DCP WG への正式採択呼びかけを発出。回答期限は 4/30。Torsten Lodderstedt（4/15）、Brian Campbell、Kristina Yasuda、Giuseppe De Marco、Paul Bastian、Orie Steele、Yaron Zehavi、Gail Hodges、David Chadwick、Pedro Felix、Javier Ruiz Aranguren、Jan Vereecken、Christian Bormann、Gabe Cohen（Block/TBD）、Oliver Terbu、Bjorn Hjelm、Juba Saadi、Judith Kahrer、Adam Cooper（OIX）の **19 名から異議なしの賛成表明** が ML 上で連続投稿された
- **OID4VP の Browser API プロファイル PR [#155](https://github.com/openid/OpenID4VP/pull/155) 起票（4/14, Torsten Lodderstedt）と 4/19 Silicon Valley ハイブリッドコールでの議論集中**: W3C Digital Credentials API（旧 Browser API）に対する OID4VP プロファイル化の最初の具体案。`expected_origins` による replay 防止と「browser vendor からの前向き合意」を確認した IIW 連動の重要 PR
- **OID4VP Implementer's Draft 3（ID3）公開の延期決定**: Joseph Heenan が 4/26 [#000280](https://lists.openid.net/pipermail/openid-specs-digital-credentials-protocols/Week-of-Mon-20240415/000280.html) で「Browser API PR #155 のマージ」と「クエリ言語議論 ([#144](https://github.com/openid/OpenID4VP/issues/144))の決着」の 2 点が片付くまで ID3 を出さないことを提案。WG 内に異論なし
- **PE 後継クエリ言語の要件議論本格化（OID4VP Issues [#144](https://github.com/openid/OpenID4VP/issues/144), [#157](https://github.com/openid/OpenID4VP/issues/157)〜[#162](https://github.com/openid/OpenID4VP/issues/162), [#164](https://github.com/openid/OpenID4VP/issues/164)）**: Sakurann が 4/4 に [#144](https://github.com/openid/OpenID4VP/issues/144)（要件ドキュメントの Google Doc 共有）を起票し、4/25 に「mandatory to implement」を巡る 6 件の分岐 Issue を IIW 議論を踏まえて整理。Presentation Exchange v2 からの脱却に向けた仕様設計の本格的入口
- **業界イベント連続による通常コール大量取消**: 4/9 / 4/11 は OAuth Security Workshop 2024（Rome）、4/16 / 4/18 は Internet Identity Workshop 38（IIW 38, Mountain View）と業界イベントが連続し、APAC コール 2 回・EU コール 2 回の合計 **4 セッションがキャンセル**。代わりに **4/19 9:30-12:30 PT に Google Sunnyvale オフィス（242 Humboldt Ct, Zebra Shark ルーム）で 3 時間ハイブリッドコール**を実施

WG 主要メンバー（Kristina Yasuda、Mike Jones、John Bradley、Joseph Heenan、Daniel Fett、Torsten Lodderstedt、Tobias Looker、Oliver Terbu、Paul Bastian、Brian Campbell、Christian Bormann、Tim Cappalli、Gail Hodges、David Chadwick、Sebastien Bahloul、Juba Saadi、Andres Olave 他）は 4/9-12 OAuth Security Workshop 2024（Rome）、4/15 OIDF Workshop at Google（Sunnyvale）、4/16-18 IIW 38（Mountain View）、4/19 DCP WG Hybrid（Google Sunnyvale）と 4 連続の対面・ハイブリッドイベントを横断する形で活動した。`openid-specs-digital-credentials-protocols` ML 上の 4 月投稿は通算 **49 件**（メッセージ番号 000244〜000292）で、月の前半（OID4VCI ID1 承認関連）・中盤（Call for Adoption と IIW 議論）・後半（4/19 Hybrid を受けた具体 PR / Issue の起票）の 3 山構造であった。

## 2. 公開された仕様・ドラフト改訂

### OpenID for Verifiable Credential Issuance 1.0 第 1 次 Implementer's Draft 承認（2024-04-01）

4 月最大の節目は、4 月 1 日に OpenID Foundation メンバーシップが **OID4VCI 1.0 を第 1 次 Implementer's Draft (ID1) として承認** したことである。Marie Jordan（OIDF Secretary）による正式アナウンスが [ML #000244](https://lists.openid.net/pipermail/openid-specs-digital-credentials-protocols/Week-of-Mon-20240401/000244.html)（2024-04-01）として DCP WG ML にも転送された。

- **投票結果**: 賛成 79 / 反対 2 / 棄権 12（総投票 93 票、会員 321 名中 29%、20% クォーラム充足）
- **承認版 URL**: [`openid-4-verifiable-credential-issuance-1_0-ID1.html`](https://openid.net/specs/openid-4-verifiable-credential-issuance-1_0-ID1.html)
- **WG 帰属**: openid.net 公式アナウンス（[Implementer's Draft of OpenID for Verifiable Credential Issuance Approved](https://openid.net/implementers-draft-of-openid-for-verifiable-credential-issuance-approved/)）では当時「a product of the OpenID Connect Working group」と表記。同日中に Michael Jones（[#000245](https://lists.openid.net/pipermail/openid-specs-digital-credentials-protocols/Week-of-Mon-20240401/000245.html)）、Gail Hodges（[#000246](https://lists.openid.net/pipermail/openid-specs-digital-credentials-protocols/Week-of-Mon-20240401/000246.html)）、Harrison（[#000247](https://lists.openid.net/pipermail/openid-specs-digital-credentials-protocols/Week-of-Mon-20240401/000247.html)）が祝賀コメントを WG ML に投稿
- **意義**: Implementer's Draft は「実装者への IP 保護を提供する安定版」と定義されており、OID4VCI が **実装プロジェクトが知財条項の安心の下で本格採用可能になる最初のマイルストーン** となった

ID1 承認直後の 4 月 4 日 SIOP/DCP コール（[#000257](https://lists.openid.net/pipermail/openid-specs-digital-credentials-protocols/Week-of-Mon-20240401/000257.html)、Joseph Heenan）では「OID4VCI advanced to First Implementer's draft status, requiring a call for adoption to transition from the Connect Working Group to the DCP WG」と整理されており、本月後半の Call for Adoption（4/15 発出）の準備段階としても位置づけられた。

### OID4VP の ID3 公開延期決定

[ML #000280](https://lists.openid.net/pipermail/openid-specs-digital-credentials-protocols/Week-of-Mon-20240415/000280.html)（Joseph Heenan、2024-04-26）で **「Browser API PR [#155](https://github.com/openid/OpenID4VP/pull/155) のマージとクエリ言語議論（Issue [#144](https://github.com/openid/OpenID4VP/issues/144)）の決着が完了するまで ID3 を出さない」** ことが提案された。本月時点での ID3 ターゲット項目は [milestone 1](https://github.com/openid/OpenID4VP/milestone/1) に整理されていたが、Browser API という **W3C との横断的な仕様調整** とクエリ言語の **Presentation Exchange v2 からの構文的脱却** という 2 つの大物が残っていることが ID3 延期の決定打となった。本提案は WG 内で異論なく受容され、結果として OID4VP ID3 は 2024 年内には公開されない方針が 4 月末の時点で確定した。

### 5-3. [openid/OpenID4VP#156](https://github.com/openid/OpenID4VP/issues/156) — Transaction Authorization using Credential Presentations

- **起票**: 2024-04-16、tlodderstedt
- **クローズ**: 2024-06-17

Torsten Lodderstedt が **EUDI Wallet 文脈** で起票。「send transaction data with the presentation request, eg the document to be signed, which causes the wallet to show this data to the user and gather consent」と概念を明示。Wallet がユーザに transaction 情報を表示し、ユーザ承認後に署名済 credential presentation に組み込む流れで、**電子署名・決済の authorization** を実装する設計案。

本 Issue は 4/30 APAC コールで Mike Jones の「cross-device flow での sensitive transaction data 露出のプライバシー懸念」と Torsten の「PR #59 merge により利用可能になった request encryption を用いた payment_confirmation walkthrough」の対比議論を引き起こし、5 月以降の `transaction_data` 関連 4 Issue 群（[#168](https://github.com/openid/OpenID4VP/issues/168) / [#172](https://github.com/openid/OpenID4VP/issues/172)〜[#174](https://github.com/openid/OpenID4VP/issues/174)）への分解の起点となった。

### 5-4. [openid/OpenID4VCI#293](https://github.com/openid/OpenID4VCI/pull/293) — rework credential and batch credential endpoint

- **起票**: 2024-04-15、paulbastian
- **マージ**: 2024-06-12（4 月時点は未マージ）

Paul Bastian 起票。Issue [#93](https://github.com/openid/OpenID4VCI/issues/93)「credential copies issuance」を解決する PR で、Credential Endpoint に **`proofs[]` 配列**を導入して同一データセットの複数 credential を 1 リクエストで発行可能にする基盤的再設計。

- **論点 1**: proofs 配列は key value のみで proof_type は外出しすべきか
- **論点 2**: issuer metadata に proofs サポートを追加すべきか
- **論点 3**: 別 batch credential endpoint を残すか・削除するか・議論延期するか

**「The proposed solution was successfully tested at the IDunion hackathon in April 2024」** と PR 本文で記載され、IDunion ハッカソン（ドイツの SSI 実装相互運用イベント）での実装検証が並行進行していた点が本月の重要な記録。4/19 Hybrid 後の WG ML で「batch issuance を別 endpoint ではなく Credential Request 拡張で対応」とコンセンサスが形成され（4/23 APAC コール議事録）、本 PR が DCP WG の正式採択方向となった。

### 5-5. [openid/OpenID4VCI#300](https://github.com/openid/OpenID4VCI/issues/300) — Add a mechanism for notifying the wallet about certain events

- **起票**: 2024-04-18、awoie (Oliver Terbu)

Oliver Terbu が IIW 38 期間中に起票。Issuer から wallet（または wallet backend）に **イベント通知**を送る仕組みを OID4VCI に追加する提案。3 つの目的:

1. Deferred issuance endpoint へのポーリング削減
2. リスクイベント（fraud / key compromise）の通知
3. Credential ライフサイクル変化（revocation / 新規発行可能種別）の通知

「OIDF Shared Signals and related IETF standards work」との連携を示唆し、push / pull 両方のメカニズム対応を要求。Wallet が複数 issuer 関係を管理する負荷を軽減するため push が推奨される、と論点を整理。Shared Signals WG（SSF / CAEP）との横断的連携の最初の WG 内提案。

### 5-6. [openid/OpenID4VCI#302](https://github.com/openid/OpenID4VCI/issues/302) — How to indicate certain credential configurations need oauth client attestation?

- **起票**: 2024-04-24、awoie

Oliver Terbu 起票。**Wallet attestation（OAuth client attestation）** を要求する credential configuration とそうでない configuration を Issuer Metadata 上で識別する手段が必要かを問う Issue。2 つの設計問:

1. credential configuration ごとに client attestation 要否を示すメカニズムが必要か
2. `token_endpoint_auth_methods_supported` に列挙する形で client attestation 用の token endpoint auth method を定義すべきか

「the issue might belong in a different repository」と本人が言及するように、OAuth WG のドラフト（draft-ietf-oauth-attestation-based-client-auth）との境界整理が必要な論点。EU 文脈の wallet attestation 議論（OSW 2024 アンカンファレンスでも取り上げ予定）と直結。

### 5-7. [openid/OpenID4VCI#305](https://github.com/openid/OpenID4VCI/issues/305) — Support credential requests which communicate only the public key instead of the pop

- **起票**: 2024-04-25、tplooker (Tobias Looker)

Tobias Looker 起票。**ユーザ認証を要する暗号鍵を用いる wallet** で、credential 複数 copy の issuance 時に毎回 proof of possession を要求するとユーザ認証が繰り返される UX 問題を提起。proof type に **`jwk` および `COSE_Key` 単体（公開鍵のみ）** を追加する案を提示。`1.1 or later` マイルストーン指定。

本 Issue は 5 月以降の `proofs[]` 配列議論（PR #293）や c_nonce / proof 必須性議論（Issue #331）と並列して、credential issuance における proof 設計の根本的問い直しの 1 系統となった。

### 5-10. [openid/OpenID4VCI#308](https://github.com/openid/OpenID4VCI/issues/308) — mso_mdoc response is underspecified（4/30 起票、5/1 close）

Oliver Terbu（awoie）が IIW / 4/19 Hybrid 後の整理として起票。Credential Response の `credential` claim が「base64url-encoded representation of the issued Credential」と書かれているが、**「Credential」自体が未定義** で、実装者は ISO 18013-5:2021 の `IssuerSigned` 構造（MSO + namespace データ要素）を使用していると指摘。Section A.2.4 への明示追加を要請。短命 Issue だが、ISO mdoc プロファイルの仕様文言精度を測る記録として有効。
