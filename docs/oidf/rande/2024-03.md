# OpenID Foundation R&E WG 活動レポート (2024年3月)

> 執筆日: 2026-05-22（2024 年 3 月活動の遡及レポート）

## 1. 概要

R&E WG（Research and Education Working Group）は、研究・教育（R&E）セクターでの OpenID Connect 採用を促進するため、R&E 向け OpenID Connect プロファイル、R&E 固有のクレーム・スコープ、エンティティメタデータ拡張の策定を目的とする OpenID Foundation のワーキンググループである。WG 議長は Davide Vaghetti（GARR の Identity Federation サービス責任者、eduGAIN の Service Owner、GitHub では `daserzw` で活動）が務め、議事録は伝統的に非公開（non-public）で、OIDF 配下の公式 GitHub リポジトリも公開されていない。[WG ページ](https://openid.net/wg/rande/) の Meeting Schedule 欄は「–」表示のままで、定例コール開催の頻度は外部から把握できない。

2024 年 3 月の R&E WG は、後続の 4〜9 月と同様に OIDF 配下での公式公開アウトプット（仕様ドラフト・公式 ML 投稿・公式 GitHub アクティビティ）を残さなかった月である。`openid-specs-rande` ML の公開アーカイブには 2024 年 3 月相当の週次インデックス（Week-of-Mon-20240226 / 20240304 / 20240311 / 20240318 / 20240325）が**一切存在せず**、同アーカイブで 2024 年に存在する公開エントリは「Week of Monday 1 January 2024」（Mike Leszcz による OIDF 理事選挙開票通知 1 通のみ）のあと、次は「Week of Monday 21 October 2024」まで連続して投稿ゼロが事実として確認できる。R&E WG の [仕様一覧](https://openid.net/wg/rande/specifications/) も Final / Implementer's Drafts / Drafts の三カテゴリすべて「None yet.」のままで、当月中に新規ドラフト・投票・パブリックレビュー告知のいずれも発生していない。

一方、2024 年 3 月は R&E WG が依拠する **OpenID Federation 1.0 が draft 33（2024-02-23 公開）を当月の作業対象版とし、`openid-specs-ab` ML 上で Federation 関連の technical issue が連番 #2123 〜 #2138 で集中的に提起された月**である。draft 33 のエディタには Sikt（ノルウェーの教育省直属の R&E 向けサービス機関）の A.Å. Solberg が引き続き名を連ねており、R&E セクター実装者が Federation 本体仕様策定の中核に座り続けている構造は 3 月時点で既に確立していた。これらの issue は翌 4-04 公開の draft 34 へ反映され、さらに 5-17 の WGLC（draft 35）→ 5-31 draft 36（ID4 候補）の流れに乗ることになるが、3 月時点では **WGLC 移行を視野に入れた issue 提起ラッシュの初動段階**にあった。

加えて 2024 年 3 月は、OIDF 全体としては **OpenID for Verifiable Credential Issuance（OID4VCI）1.0 の Implementer's Draft（ID1）化に向けた Notice of Vote が 3-11 に発出された月**でもある。同通知（Marie Jordan / Secretary, OIDF 発）では、Early voting 開始 3-18、Official voting 3-25 〜 4-01 の日程が明示され、3 月後半は OIDF 全体として ID1 投票期間に入っていた。R&E WG 自身は OID4VCI の所掌外だが、欧州の研究・教育セクターでも EUDI Wallet の進展と並行して Verifiable Credentials が中長期の検討対象となりつつあり、上位フレームワークの ID1 化プロセス開始は周辺コンテキストとして注目すべきマイルストーンである。

2024 年 3 月の R&E 関連活動を整理すると、次の 4 点が中心となる。

- **OpenID Federation 1.0 draft 33（2024-02-23 公開版）を作業対象とした issue 棚卸しの本格化**。`openid-specs-ab` ML 上で Issue #2123 〜 #2138 が 3-02 〜 3-29 にかけて集中提起。Michael Jones、Vladimir Dzhuvinov（Connect2id）、Roland Hedberg らが中心。Sikt の A.Å. Solberg は引き続きエディタとして仕様編集に関与
- **OID4VCI 1.0 ID1 Notice of Vote 発出（2024-03-11）**。Early voting 3-18、Official voting 3-25 〜 4-01 の日程。R&E WG 直接の所掌外だが、欧州 R&E 連携において EUDI Wallet との接続点として中長期の関心領域
- **GEANT/edugain-openidfed リポジトリで月内 8 コミット**。3-03 と 3-06 にイタリア デジタル変革省由来の peppelinux（Federation 1.0 エディタの Giuseppe De Marco）による eduGAIN OpenID Federation 文書群の構造整備、3-17 にロール別 Configuration steps の追記。R&E WG 議長 Vaghetti 自身のコミットは月内なし
- **`openid-specs-rande` ML 投稿ゼロ、R&E WG 自身のドラフト「None yet.」、議事録 non-public** の三重沈黙が継続。WG メンバーの実体作業は GÉANT GN5-1 WP5 / Sikt / GARR / SURF 等の R&E セクター内部基盤側で進行中だったと推定される

`openid-specs-rande` ML への公開投稿ゼロ、R&E WG 自身のドラフト「None yet.」、議事録 non-public という三重の沈黙が続く一方で、依拠する Federation 本体仕様が **Issue #2123 〜 #2138 の連番提起によって draft 34 直前の編集論点を可視化**し、隣接の `GEANT/edugain-openidfed` リポジトリでは Federation 1.0 エディタの De Marco が直接コミットを重ねていたのが 2024 年 3 月の R&E WG 周辺の構図である。

#### Issue #2123（Federation 原則の Introduction 追記）

Michael Jones が 2024-03-02 18:13 UTC に [010262](https://lists.openid.net/pipermail/openid-specs-ab/2024-March/010262.html) で提起。Federation 仕様の Introduction に以下 2 つの基本原則を明示することを提案:

- **Mutual agreement（相互合意）**: エンティティがフェデレーションに参加する際、参加者はフェデレーションのルールに従う一方、フェデレーションも予測可能かつ仕様どおりに動作することが求められる。両者は「相互合意」の関係にある
- **Individual entity perspective（各エンティティの視点）**: 「each entity's view matters」。中間エンティティは自身の上位が課す要件よりも厳しいメタデータ要件をサブオーディネートに課すことが許される。この裁量権が原則として認められるべきである

これらは「すべての関係者が理解しておくべき重要原則」として Introduction 冒頭に近い位置に置くべきであるという編集提案で、Federation 仕様の読み手（R&E セクターを含む）に対する設計思想の伝達に関わる根本的な論点である。R&E ドメインでは eduGAIN 中間エンティティが配下のフェデレーション参加者に対して追加要件（属性リリース・トラストマーク等）を課す運用が現実的に想定されており、本原則の明文化は R&E セクターの実装解釈に直結する。

#### Issue #2135（Metadata Policy における space-separated list 例外の絞り込み）

Vladimir Dzhuvinov が 2024-03-20 に [010280](https://lists.openid.net/pipermail/openid-specs-ab/2024-March/010280.html) で提起。論点:

- 現行 draft 33 では metadata_policy 評価時に「space-separated string を JSON array と同等に扱う」例外規定が広く適用されている
- この例外を **`scope` oauth_client metadata パラメータ専用に限定すべき** である
- 文法仕様が明示されていない他のメタデータパラメータにこの例外を広く適用すると、metadata_policy オペレーションに期待される決定論的挙動を損なう可能性がある
- Federation 仕様は `scope` エンコーディング周辺の歴史的経緯から学び、同様の慣行を将来的に推奨しない方向で整備すべき

これは Federation Metadata Policy の拡張性と決定性のトレードオフを整理する論点で、後の draft 34 / 35 / 36 系列での Metadata Policy 節整理に直接寄与した。

#### Issue #2138（Entity Statements における JWT `kid` ヘッダ要件）

Vladimir Dzhuvinov が 2024-03-29 に [010284](https://lists.openid.net/pipermail/openid-specs-ab/2024-March/010284.html) で提起。Entity Statements の JWT ヘッダにおける `kid` クレームの要求/任意の扱いを整理し、署名検証時の鍵特定プロセスを実装間で一致させる論点。R&E セクターの Federation 実装（eduGAIN OpenID Federation PoC を含む）でも署名鍵ローテーション運用に直結する論点である。

### R&E WG 定例コール

R&E WG 自身の 3 月中の定例コール開催の有無は、公式チャネル（openid.net/wg/rande/、`openid-specs-rande` ML）のいずれでも確認できない。openid.net/wg/rande/ のミーティング欄が「–」のままであり、ML 投稿は当月ゼロである。R&E WG メンバーの中心層は、(1) Federation draft 33 を作業対象とする Connect WG ML 上 issue 提起・レビュー作業、(2) GN5-1 WP5 配下の eduGAIN OpenID Federation PoC 立ち上げ準備（Q2 2024 開始直前のフェーズ）、(3) AARC TREE プロジェクト（2024-03-01 開始）初月のキックオフフェーズで多忙だった可能性が高い。WG 内部の非同期議論は、非公開の WG 定例チャネル、REFEDS Slack、GÉANT 内部 ML、GN5-1 WP5 confluence 等で進行していたと見られるが、外部からは追跡できない。

### 隣接コミュニティ: REFEDS OIDCre

## 5. GitHub 上の議論

R&E WG の **OIDF 配下の公式** GitHub リポジトリは存在しない。openid.net/wg/rande/ にも公開リポジトリへの参照はない。

3 月時点では、後に R&E WG が依拠する OpenID Federation 本体仕様の `openid/federation` GitHub リポジトリも本格運用前で（移行宣言は 2024-07-29、最初の README.md / CONTRIBUTING.md 作成は 6-18）、仕様編集の主な場は Bitbucket Cloud の `bitbucket.org/openid/connect` だった。Federation 関連 issue は §3 / §4 で示したとおり Bitbucket 上の #2123 〜 #2138 の系列を占めており、R&E セクター実装者が当時 issue を投じる経路は Bitbucket Cloud に限られていた。

### R&E 隣接の公開リポジトリ（3 月の動向）

- **[GEANT/edugain-openidfed](https://github.com/GEANT/edugain-openidfed)** : eduGAIN 向け OpenID Federation トラストモデル文書群。**2024 年 3 月内のコミット 8 件**を確認:
  - 2024-03-03: `f8bc887` "GA editorials"、`55d4034` "federation main structure completed without considerations"、`f3eec4c` "federation_entity note"、`8a984a9` "federation exampels structure"（いずれも peppelinux / Giuseppe De Marco）
  - 2024-03-06: `b6b3709` "fix: typo Lead -> Leaf"、`b1f1985` "fix: OpenID4RS-OpenIDFederation.md source_endpoint in Subordinate Statement"（peppelinux）
  - 2024-03-17: `9e2ef08` "[Federation] Configuration steps by roles"、`a4708a6` "Merge branch 'main'"（peppelinux）
  - すべて Federation 1.0 共同エディタの Giuseppe De Marco（peppelinux、独立 / イタリア デジタル変革省）による直接コミット。R&E WG 議長 Vaghetti（`daserzw`）の月内コミットは確認できない。3-17 以降は次のコミット（6-12 Vaghetti による README.md 更新）まで間が空く
- **[refeds-oidcre/eduperson-jwt-claims](https://github.com/refeds-oidcre/eduperson-jwt-claims)** : eduPerson／SCHAC 属性を JWT クレームとして伝達するためのドラフト仕様。2024 年 3 月の新規アクティビティなし。最新コミットは 2016 年 1 月で長期休眠

なお、GN5-1 WP5 配下で開発されていた eduGAIN OpenID Federation PoC の実装ツール群は、3 月時点では公開リポジトリの形では集約されておらず、コードは GÉANT 内部 GitLab／個別開発者の GitHub アカウントに分散していた。Q2 2024 開始直前のフェーズで、9-17 の T&I Incubator Public Sprint Demo に向けた実装作業がまだキックオフ前の準備段階にあったと推定される。

## 6. 関連イベント

### OID4VCI 1.0 ID1 Notice of Vote 発出（2024-03-11）

§2 で詳述。R&E WG 直接の所掌外だが、欧州 R&E 連携（GÉANT、AARC、eduGAIN）が中長期で EUDI Wallet 連携と OID4VCI 採用を検討する文脈で重要な手続上のマイルストーン。

### IETF 119 ブリスベン（2024-03-16 〜 03-22）

3 月中旬の IETF 119 ブリスベン会合では OAuth WG / WIMSE WG 等で関連議題が取り上げられた。R&E セクター直結のセッションは確認できないが、Federation 仕様策定に関わるエディタ陣（Mike Jones、Roland Hedberg、Vladimir Dzhuvinov）は IETF / OIDF 横断で活動しており、3 月後半から 4 月にかけての Connect WG ML 上 issue 提起ラッシュは IETF 119 直前後の温度感を反映している。

### AARC TREE プロジェクト 始動（2024-03-01 開始）

[AARC TREE](https://aarc-community.org/aarc-tree-project/)（AARC Technical Revision to Enhance Effectiveness、Horizon Europe Grant Agreement 101131237）は **2024 年 3 月 1 日に正式開始した EU 共同プロジェクト**（期間 2 年、2026-02-28 まで）で、3 月 11-13 日には Utrecht でキックオフミーティングが開催された。AARC TREE は AARC Blueprint Architecture の改訂を中心に据え、研究・教育コミュニティにおける Authentication and Authorisation インフラの相互運用性向上を目的とする点で R&E WG の関心領域と直結する。3 月は初月キックオフフェーズに当たる。

### eduGAIN OpenID Federation Pilot（GN5-1 WP5、Q2 2024 開始直前）

GN5-1 WP5 配下で運営される PoC / Pilot は、OpenID Federation を eduGAIN の将来トラスト技術として評価するもので、Q2 2024（4 月）の本格始動を 3 月時点で準備していた段階。R&E WG 議長 Vaghetti 本人が GARR の立場で PoC をリードしており、隣接の `GEANT/edugain-openidfed` リポジトリでは Federation 1.0 共同エディタの De Marco が直接コミットを重ねていた（§5 で詳述）。

## 7. 今後の予定（2024 年 3 月末時点の視点）

3 月末時点で R&E コミュニティが注視していた次月以降の動向は以下のとおり。

- **OID4VCI 1.0 ID1 投票完了（2024-04-01 まで）**: 3-25 開始の Official voting が 4-01 まで継続。承認可否のアナウンスが翌月初頭に公表される見込み
- **OpenID Federation 1.0 次期 Editor's Draft（draft 34）公開予定**: 3 月内に積み上がった Issue #2123 〜 #2138 を反映した次期版が翌 4 月に公開される見込み
- **eduGAIN OpenID Federation PoC 本格始動（Q2 2024）**: GN5-1 WP5 配下の検証作業が 4 月から本格開始予定
- **AARC TREE プロジェクトの WP 編成**: 3-01 開始から本格的な WP 活動と Landscape analysis（D3.1）の編集着手
- **Identiverse 2024（2024-05-28 〜 05-31、ラスベガス）**: 2 か月後開催の業界最大級デジタルアイデンティティイベント
- **EIC 2024（2024-06-04 〜 06-07、ベルリン）**: 3 か月後開催の欧州最大級デジタルアイデンティティイベント。Federation や EUDI Wallet 関連発表が見込まれ、R&E セクター関係者の参加も期待される
- **R&E WG 自身のドラフト整備**: OIDF 配下の公式仕様は引き続き「None yet.」のまま。OIDF 配下での対外可視性の改善は継続課題

3 月末時点での R&E WG の対外可視性は、OIDF 配下の ML・GitHub・ドラフトいずれにも公開アウトプットを残さない状態が継続している一方で、依拠する Federation 本体仕様で **Issue #2123 〜 #2138 という 16 連番の編集論点提起**が達成され、Sikt の Solberg がエディタとして関与し続け、隣接の `GEANT/edugain-openidfed` リポジトリでは Federation エディタの De Marco が直接コミットを重ねるという構造が当月のデータ分布から読み取れる。R&E 仕様策定の実体作業が OIDF 配下から GÉANT GN5-1 WP5 / Sikt / GARR / SURF 配下へ重心を移していく構造が 3 月時点で既に確立していたことを示すデータ群である。
