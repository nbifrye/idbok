# OpenID Foundation R&E WG 活動レポート (2024年1月)

> 執筆日: 2026-05-22（2024 年 1 月活動の遡及レポート）

## 1. 概要

R&E WG（Research and Education Working Group）は、研究・教育（R&E）セクターでの OpenID Connect 採用を促進するため、R&E 向け OpenID Connect プロファイル、R&E 固有のクレーム・スコープ、エンティティメタデータ拡張の策定を目的とする OpenID Foundation のワーキンググループである。WG 議長は Davide Vaghetti（GARR の Identity Federation サービス責任者、eduGAIN の Service Owner、GitHub では `daserzw` で活動）が務め、議事録は伝統的に非公開（non-public）で、OIDF 配下の公式 GitHub リポジトリも公開されていない。[WG ページ](https://openid.net/wg/rande/) の Meeting Schedule 欄は「–」表示のままで、定例コール開催の頻度は外部から把握できない。

2024 年 1 月の R&E WG は、後続の 2 月以降と同様に OIDF 配下での公式公開アウトプット（仕様ドラフト・公式 WG 単独投稿・公式 GitHub アクティビティ）を残さなかった月である。`openid-specs-rande` ML の公開アーカイブには 2024 年 1 月相当の週次インデックスとして「Week of Monday 1 January 2024」のみが存在し、内容は Mike Leszcz による **2024 OIDF Board Elections 投票開始通知（2024-01-03 17:36 UTC）1 通のみ**。1 月 8 日週以降（Week-of-Mon-20240108 / 20240115 / 20240122 / 20240129）の週次インデックスは公開アーカイブ上に**生成されておらず**、当月の `openid-specs-rande` への WG メンバー間技術投稿は皆無である。R&E WG の [仕様一覧](https://openid.net/wg/rande/specifications/) も Final / Implementer's Drafts / Drafts の三カテゴリすべて「None yet.」のままで、当月中に新規ドラフト・投票・パブリックレビュー告知のいずれも発生していない。

一方、2024 年 1 月は OIDF 全体および R&E が依拠する OpenID Federation 1.0 にとって**極めて密度の濃い月**であり、R&E WG 周辺の構図を理解する上では以下の事象群が同時進行で起きていた点を押さえる必要がある。

- **OIDF 理事選挙の投票期間（2024-01-02 〜 2024-01-16）と結果公表（2024-01-17）**。Community Representatives 枠に Mike Jones が新規当選、George Fletcher が再選。Corporate Representatives 枠には Atul Tulshibagwale（SGNL）と Mark Verstege（CDR Australia）が当選
- **`openid-specs-ab` ML 上で Federation Issue #2102 〜 #2110 の 9 連番が提起**。Stefan Santesson（Swedish Federation 実装者）が #2102 / #2103 / #2104 / #2105 / #2106 / #2107 を立て続けに起票し、Nat Sakimura が #2108（National Identity Schemes トラッキング）、Giuseppe De Marco（peppelinux）が #2109 / #2110 を提起。R&E セクターが依拠する Federation 本体仕様の編集論点が一気に積み上がった月
- **OID4VCI 1.0 Implementer's Draft（ID1）化に向けた Working Group Last Call（WGLC）の発出と承認**。Michael Jones が 2024-01-16 に WGLC 通知を発出（[010204](https://lists.openid.net/pipermail/openid-specs-ab/2024-January/010204.html)）、1 月 22 日 EOD PST を WG コンセンサス確認の deadline として設定。後続の 45 日パブリックレビュー期間は 2 月初頭に開始される
- **OpenID Summit Tokyo 2024（2024-01-19、東京渋谷、参加 250 名超）開催**。OpenID Connect 10 周年記念パネルが企画され、Gail Hodges（OIDF Executive Director）による SIDI Hub 報告と 2024 年戦略アウトルックの発表、Mike Jones モデレートの記念パネル（パネリスト: Nat Sakimura、Nov Matake、Ryo Ito）、Sakimura のクロージング基調講演が実施された
- **OIDF が CFPB Rule 1033（Open Banking）に関する意見書を公表（2024-01-03 openid.net 記事）**。米国 CFPB の Open Banking 規則案に対し、業界標準プロトコルの使用要求・コンフォーマンス認証・メタデータと信頼メカニズムの確立を提言（意見書本体は 2023-12-29 提出）
- **OpenID for Verifiable Credentials の形式的セキュリティ解析公表（2024-01-18）**。Fabian Hauck（University of Stuttgart 修士論文、指導 Daniel Fett 博士・Pedram Hosseyni、審査 Ralf Küsters 教授、IDunion プロジェクトと Verimi GmbH の支援）による OID4VCI / OID4VP の Web Infrastructure Model に基づく解析結果が openid.net で公表
- **GEANT/edugain-openidfed リポジトリの新規作成（2024-01-22）**。Giuseppe De Marco による Initial commit を含む計 6 コミットがすべて 1-22 当日に投入され、eduGAIN 向け OpenID Federation トラストモデル文書の公開リポジトリが誕生

2024 年 1 月の R&E WG 周辺を一言で要約すれば、「`openid-specs-rande` ML は事務通知 1 通のみで沈黙し、WG 自身の公開ドラフトは依然『None yet.』、議事録は non-public のまま」という三重の沈黙が続く一方で、(a) Federation 本体仕様の編集論点が #2102 〜 #2110 で 9 連番として可視化され、(b) eduGAIN 向け Federation トラストモデル文書を集約する公開リポジトリ `GEANT/edugain-openidfed` が 1-22 に誕生し、(c) OID4VCI 1.0 が ID1 化プロセスに正式に乗り出し、(d) OIDF 理事会には Connect 10 周年の象徴である Mike Jones が新規当選した、という構図である。R&E 仕様策定の実体作業が OIDF 配下から GÉANT GN5-1 WP5 / Sikt / GARR / SURF 配下へ重心を移していく構造的傾向の萌芽が、`GEANT/edugain-openidfed` リポジトリ誕生という形で 1 月時点から具体化したと読み取れる。

## 3. ミーティングと議論

R&E WG の定例コール議事録は伝統的に non-public 運用であり、2024 年 1 月の定例コール開催日・参加者・議論内容は公開されていない。openid.net/wg/rande/ のミーティング欄も「–」表示のままで、定例の頻度は不定とされている。OIDF カレンダー（[openid.net/calendar/](https://openid.net/calendar/)）の現時点表示でも 2024-01 の R&E WG エントリは確認できない。

本節では R&E WG の活動文脈に直接関係し、公開記録が残るプロセス上の議論を整理する。

### Connect WG ML 上の Federation Issue 棚卸し（2024-01 月内）

Federation 仕様 draft 32 を出発点として 2-23 公開予定の draft 33 へ向かう編集作業の起点として、`openid-specs-ab` ML 上では 1 月中に Federation 関連の technical issue が **#2102 〜 #2110 の 9 連番** で提起された。主要 issue:

| Issue | 提起者                         | 概要                                                          |
| ----- | ------------------------------ | ------------------------------------------------------------- |
| #2102 | Stefan Santesson               | Subject data publication のための新 Entity Statement クレーム |
| #2103 | Stefan Santesson               | Entity Statements における constraints の定義の曖昧さ         |
| #2104 | Stefan Santesson               | Subordinate Statements での Trust Marks 許容                  |
| #2105 | Stefan Santesson               | combined policy example                                       |
| #2106 | Stefan Santesson               | [FEDERATION] Intermediate Entity Example                      |
| #2107 | Stefan Santesson               | Trust Mark endpoints での client assertion 要件緩和と拡張性   |
| #2108 | Nat Sakimura                   | OpenID Connect を使う National Identity Schemes の追跡        |
| #2109 | Giuseppe De Marco (peppelinux) | [Federation] List Endpoint レスポンス形式                     |
| #2110 | Giuseppe De Marco (peppelinux) | [Federation] listing endpoint における複数 entity_type        |

**Stefan Santesson が #2102 〜 #2107 を立て続けに 6 件起票している点が 1 月の特徴**である。Santesson は Swedish Federation 実装者（IDsec Solutions）として、Sweden の Federation 展開（後の 2-23 draft 33 公開告知文で Jones が謝意を示すレビュー作業の起点）の中で生じた具体的な実装課題を ML 上で次々と論点化していた。

#### Issue #2102（Subject data publication のための新 Entity Statement クレーム）

Santesson による提起。Entity Configuration を well-known location で publish できない leaf entity を Resolver の bottom-up path building で発見できない問題に対し、Subordinate Statement 内に「subject がどこで Entity Configuration を publish するか／しないか」を示す新クレームを導入する提案。

Santesson の表現を引用すれば「The motivation behind this claim is to allow validation of leaf entities that do not have the capability to create and publish Entity Configuration」（[010185](https://lists.openid.net/pipermail/openid-specs-ab/2024-January/010185.html) より）であり、leaf entity に対し (a) Entity Configuration の publish をスキップして Resolver の限定的可視性を受け入れる、(b) Entity Configuration を publish して広範な可視性を獲得する、の 2 経路を提供する。R&E ドメインでは、eduGAIN 配下に存在する多数の leaf SP / IdP のうち軽量実装で運用される組織が Entity Configuration publish に対応できないケースが想定されるため、本論点は R&E セクター実装にも直結する。

#### Issue #2103（Entity Statements 内 constraints 定義の曖昧さ）

Santesson による提起。Entity Statements 内で constraint を定義する際の文言と意味論の曖昧さを指摘し、明確化を求める論点。後の draft 33 で「制約定義の曖昧さを解消」として整理される基礎となる issue。

#### Issue #2104（Subordinate Statements での Trust Marks 許容）

Santesson による提起。Federation 1.0 draft 32 における「This claim MUST NOT be present in Subordinate Statements. Trust Marks are described in Section 6.3.」という制限を「unnecessary restriction that prevents legitimate extensibility」と批判し、Subordinate Statements 内でも Trust Marks を許容すべきだと主張する論点（[010198](https://lists.openid.net/pipermail/openid-specs-ab/2024-January/010198.html) より）。

Santesson の根拠は以下の三点:

- **セキュリティは損なわれない** — Trust Marks は subject に対し暗号学的に署名・束縛されており、リスクは緩和されている
- **メタデータ前例の存在** — Subordinate Entity Statements 内では既に subject に対する metadata の伝達が許容されており、Trust Marks にも同等の扱いを与えるべき
- **拡張性の恩恵** — この制約を外せば、Entity Configurations を持たない end entities を Subordinate Statements 内に埋め込んだ完全情報により支援可能となる（critical で marking すれば相互運用性も担保される）

R&E ドメインでは、eduGAIN 中間エンティティが配下フェデレーション参加者に対し Trust Marks を Subordinate Statements 経由で付与する運用が想定され、本 issue は R&E セクター固有の Trust Marks 運用パターンに直結する。

#### Issue #2108（National Identity Schemes のトラッキング）

**OIDF Chairman Nat Sakimura による起票**（[010202](https://lists.openid.net/pipermail/openid-specs-ab/2024-January/010202.html)）。起票文を引用すれば「This ticket is to track the National Identity Schemes that use OpenID Connect. Please add the names of countries that you know that use OIDC, preferably with source.」であり、OpenID Connect を採用する各国 National Identity Scheme の情報を、出典付きでコミュニティから収集することを目的とする。

R&E セクターは多くの国で National Identity Scheme と相互運用ないし併存する関係にあり（eduGAIN と national eID の組み合わせ、Belgium、Norway、Sweden、Italy 等で具体的なユースケースが議論されてきた）、Sakimura の本 issue は R&E セクター実装者にとっても情報集約点として有用な棚卸しである。

#### Issue #2109 / #2110（List Endpoint 関連、De Marco 提起）

Federation 1.0 共同エディタの **Giuseppe De Marco（peppelinux）** が月末に起票した 2 件。

- **#2109**: List Endpoint レスポンス形式を整理する論点。eduGAIN OpenID Federation PoC の実装過程で生じたフィードバックを反映した内容
- **#2110**: listing endpoint で複数 `entity_type` を扱う際の仕様明確化

De Marco は同時期に `GEANT/edugain-openidfed` リポジトリの作成（後述）と並行して、Federation 本体仕様へのフィードバックを ML 上に投げ込んでおり、R&E セクター実装の知見が Federation 本体仕様の編集論点としてループバックする経路が 1 月時点で確立しつつあった。

### R&E WG 定例コール

R&E WG 自身の 1 月中の定例コール開催の有無は、公式チャネル（openid.net/wg/rande/、`openid-specs-rande` ML）のいずれでも確認できない。openid.net/wg/rande/ のミーティング欄が「–」のままであり、ML 投稿は事務通知 1 通のみ（2024-01-03 の OIDF Board Elections 投票開始通知）である。R&E WG メンバーの中心層は、(1) OpenID Summit Tokyo 2024（1-19、東京）への参加準備および当日の参加、(2) GN5-1 WP5 配下の eduGAIN OpenID Federation PoC 立ち上げ準備（Q2 2024 開始に向けた準備フェーズ）、(3) Federation 本体仕様への Issue 提起（特に De Marco の #2109 / #2110）と `GEANT/edugain-openidfed` リポジトリ立ち上げ（1-22）に注力していたと見られる。WG 内部の非同期議論は、非公開の WG 定例チャネル、REFEDS Slack、GÉANT 内部 ML、GN5-1 WP5 confluence 等で進行していたと見られるが、外部からは追跡できない。

### OIDF CFPB Rule 1033 意見書公表（2024-01-03）

OIDF は米国 CFPB（Consumer Financial Protection Bureau）が提案する Open Banking 規則 1033 に対する [意見書](https://openid.net/oidf-comments-cfpb-rule-1033-regarding-open-banking/) を 1-03 に openid.net 上で公表した（意見書本体は 2023-12-29 提出）。提言の主要点:

- 業界標準プロトコルの使用要求
- 実装のコンフォーマンス認証（ローンチ前と定期的な認証）
- Off-the-shelf 部品の活用による実装コスト削減
- Entity Metadata と相互運用可能な信頼メカニズム（bilateral point-to-point ではなく）
- 標準ライフサイクル管理

R&E セクターへの直接言及はないが、「Entity Metadata と信頼メカニズム」「相互運用可能な信頼アンカー」というキーワードは、OpenID Federation の R&E セクター応用と同じ概念基盤を共有しており、Open Banking と R&E が同じ Federation インフラを共有する将来像を間接的に示唆する。

### OID4VCI Formal Security Analysis 公表（2024-01-18）

University of Stuttgart の Fabian Hauck による **OID4VCI / OID4VP の形式的セキュリティ解析** が [openid.net 上で公表](https://openid.net/formal-security-analysis-openid-verifiable-credentials/) された（2024-01-18、Hauck 修士論文、指導 Daniel Fett 博士・Pedram Hosseyni、審査 Ralf Küsters 教授、IDunion プロジェクトと Verimi GmbH の支援）。

Web Infrastructure Model（Stuttgart 大が OpenID Connect / FAPI / OAuth 2.0 の解析にも用いてきた形式的 Web モデル）を用いた解析で、(a) same-device flow におけるセキュリティを確認、(b) pre-authorized code flow および cross-device シナリオにおける phishing 脆弱性の可能性を指摘した（既知の attack category であることを明示）。R&E セクターでも EUDI Wallet 連携での OID4VCI 採用が中長期で検討対象となっており、形式的解析の結果は実装者にとって参照すべき重要文書である。

### SIDI Hub ロードマップ公表（2024-01-31）

OIDF が共同創設メンバーである **Sustainable and Interoperable Digital Identity (SIDI) Hub** が 2024 年ロードマップを [openid.net で公表](https://openid.net/sidi-hub-announces-roadmap-drive-cross-board-interoperability-digital-identity/)（2024-01-31）。2023-11 のパリ Summit を踏まえ、(1) Champion Use Case の同定、(2) 最小相互運用要件の確立、(3) 国家横断 Trust Framework マッピング、(4) 成功指標の定義の 4 ワークストリームを優先課題として明示した。R&E セクター直接言及はないが、国家横断 Trust Framework マッピングは eduGAIN の越境利用と概念的に重なる領域である。

### eduGAIN OpenID Federation Pilot（GN5-1 WP5、Q2 2024 開始準備期）

GN5-1 WP5 配下で運営される PoC / Pilot は、OpenID Federation を eduGAIN の将来トラスト技術として評価するもので、Q2 2024（4 月）の本格始動を 1 月時点で準備していた段階。R&E WG 議長 Vaghetti 本人が GARR の立場で PoC をリードしており、1-22 の `GEANT/edugain-openidfed` リポジトリ誕生は本 Pilot の文書整備の一環である（§5 で詳述）。

## 7. 今後の予定（2024 年 1 月末時点の視点）

1 月末時点で R&E コミュニティが注視していた次月以降の動向は以下のとおり。

- **OID4VCI 1.0 ID1 パブリックレビュー期間開始（2024 年 2 月初頭、見込み）と 45 日レビュー**: 1-22 EOD PST の WG コンセンサス確認 deadline を経て、2 月初頭に Foundation-wide 45 日パブリックレビュー期間が開始する見込み。後続の 7 日 Official voting と合わせ、Connect WG → Digital Credentials Protocols WG への移管が ID1 承認時に予定
- **OpenID Federation 1.0 次期 Editor's Draft（draft 33）公開予定**: 1 月内に積み上がった Issue #2102 〜 #2110 およびその後追加で提起される論点を反映した次期版が翌 2 月内に公開される見込み（実際には 2-23 公開）
- **AARC TREE プロジェクト 正式開始（2024-03-01）とキックオフ（3 月、Utrecht）**: Horizon Europe 資金で 2 年間 EUR 2,500,000 規模の共同プロジェクトが 3-01 に始動予定
- **eduGAIN OpenID Federation PoC 本格始動（Q2 2024）**: GN5-1 WP5 配下の検証作業が 4 月から本格開始予定。1-22 誕生の `GEANT/edugain-openidfed` リポジトリが文書集約点
- **OIDF Workshop Sunnyvale（2024-04-15）登録開始予定**: 4 月の OIDF Hybrid Workshop @ Google Sunnyvale の登録は 2 月内に開始される見込み
- **R&E WG 自身のドラフト整備**: OIDF 配下の公式仕様は引き続き「None yet.」のまま。OIDF 配下での対外可視性の改善は継続課題

1 月末時点での R&E WG の対外可視性は、OIDF 配下の ML・GitHub・ドラフトいずれにも実質的な公開アウトプットを残さない状態が継続している（`openid-specs-rande` ML は OIDF 全 ML への定型クロスポスト 1 通のみ、公式ドラフトは「None yet.」、GitHub リポジトリは存在しない）。一方で、依拠する Federation 本体仕様で **Issue #2102 〜 #2110 の 9 連番** が立て続けに提起され、Stefan Santesson が Swedish Federation 実装者として 6 件を主導し、Federation エディタの De Marco が `GEANT/edugain-openidfed` リポジトリを 1-22 に立ち上げて Federation Issue #2109 / #2110 とリポジトリ整備を同時並行で進める構造が当月のデータ分布から読み取れる。R&E 仕様策定の実体作業が OIDF 配下から GÉANT GN5-1 WP5 / Sikt / GARR / IDsec / Italy MITD 配下へ重心を移していく構造の起点が、1 月の `GEANT/edugain-openidfed` リポジトリ誕生という形で具体化したと総括できる月である。
