# OpenID Foundation R&E WG 活動レポート (2024年6月)

> 執筆日: 2026-05-21（2024 年 6 月活動の遡及レポート）

## 1. 概要

R&E WG（Research and Education Working Group）は、研究・教育（R&E）セクターにおける OpenID Connect 採用を促進するため、R&E 向け OpenID Connect プロファイル、R&E 固有のクレーム・スコープ、エンティティメタデータ拡張の策定を目的とする OpenID Foundation のワーキンググループである。WG 議長は Davide Vaghetti（GARR の Identity Federation サービス責任者、GitHub では `daserzw` で活動）が務め、議事録は伝統的に非公開（non-public）で、OIDF 配下の公式 GitHub リポジトリも公開されていない。[WG ページ](https://openid.net/wg/rande/) の Meeting Schedule 欄は「–」表示のままで、定例コール開催の頻度は外部から把握できない。

2024 年 6 月の R&E WG は、後続の 7〜9 月と同様に OIDF 配下での公式公開アウトプット（仕様ドラフト・公式 ML 投稿・公式 GitHub アクティビティ）を残さなかった月である。`openid-specs-rande` ML の公開アーカイブには 2024 年 6 月に該当する週次インデックスが**一切存在せず**、同アーカイブで 2024 年内に公開エントリが残るのは 2024-01-01 以降では 2024-10-21（OIDF 事務局による事務告知）が次のエントリとなる。R&E WG の [仕様一覧](https://openid.net/wg/rande/specifications/) も Final / Implementer's Drafts / Drafts の三カテゴリすべて「None yet.」のままで、当月中に新規ドラフト・投票・パブリックレビュー告知のいずれも発生していない。

一方、2024 年 6 月は R&E WG が依拠する **OpenID Federation 1.0 第 4 回 Implementer's Draft（draft 36 = ID4）の 45 日間 OIDF 全体パブリックレビュー期間（2024-06-01 〜 2024-07-16）が始まった月**である。当 WG が将来策定する R&E Implementation Profile の上位基盤仕様が、第 3 回 ID（2021 年）以来約 3 年ぶりに最終投票直前の段階に到達したことになる。エディタには Sikt（ノルウェーの R&E 向けサービス機関）の A.Å. Solberg が継続して名を連ねており、R&E セクター実装者が Federation 本体仕様策定の中核に座り続けている。

加えて 6 月は、**GitHub の `openid/federation` リポジトリが立ち上げ初期作業を行った月**でもある。同リポジトリでは 6-18 〜 6-30 にかけて README.md・CONTRIBUTING.md の整備、GitHub Pages による editors' draft 公開パイプラインの構築、最初の Issue（#12, #15）と PR（#13, #14, #16, #17）の投入が行われた。Bitbucket から GitHub への完全な作業移行は 7 月末まで待つことになるが、その地ならしが当月内に行われた点は、R&E セクター実装者が将来 issue/PR で Federation 本体仕様に関与する可能性のある経路の準備が整い始めた瞬間として記録に値する。

R&E セクター側でも GÉANT の eduGAIN OpenID Federation PoC リポジトリ（[GEANT/edugain-openidfed](https://github.com/GEANT/edugain-openidfed)）に対して、R&E WG 議長 Vaghetti 本人が 2024-06-12 に README.md を更新するコミット（`1cc0b1b`）を投入している。これは OIDF 配下ではなく GÉANT GN5-1 WP5 配下の作業だが、R&E WG 議長が当月内に R&E × OpenID Federation 文脈で残した数少ない公開トレースの一つである。

2024 年 6 月の R&E 関連活動を整理すると、次の 4 点が中心となる。

- **OpenID Federation 1.0 第 4 回 Implementer's Draft の 45 日間パブリックレビュー期間開始（2024-06-01）**。WG ラストコールが 2024-05-31 に終了し、6-01 から OIDF 全体レビューへ移行。6-02 に [Public Review Period 告知](https://openid.net/public-review-period-for-proposed-fourth-implementers-draft-of-openid-federation/) が公開された
- **`openid/federation` GitHub リポジトリの整備開始（2024-06-18 〜 30）**。peppelinux（Giuseppe De Marco）が GitHub Pages 経由の editors' draft 自動公開パイプラインを構築し、README.md・CONTRIBUTING.md を整備
- **eduGAIN OpenID Federation PoC（GN5-1 WP5 配下）の継続**。R&E WG 議長 Vaghetti 自身が 6-12 に `GEANT/edugain-openidfed` の README.md を更新（コミット `1cc0b1b`）
- **OIDF 全体としての R&E 関連発信は限定的**。当月の OIDF 公式アナウンスは 6-02 の Federation Public Review Period 開始告知と 6-18 の Gail Hodges による [Digital Identity at the G20](https://openid.net/digital-identity-g20/) の 2 件のみで、後者は R&E セクターには直接言及していない

`openid-specs-rande` ML への公開投稿ゼロ、R&E WG 自身のドラフト「None yet.」、議事録 non-public という三重の沈黙が続く一方で、依拠する Federation 本体仕様が OIDF 全体パブリックレビュー入り・GitHub 上での作業基盤整備・R&E セクター側の PoC 継続という三方向の前進を見せた、それが 2024 年 6 月の R&E WG 周辺の構図である。

## 3. ミーティングと議論

R&E WG の定例コール議事録は伝統的に non-public 運用であり、2024 年 6 月の定例コール開催日・参加者・議論内容は公開されていない。openid.net/wg/rande/ のミーティング欄も「–」表示のままで、定例の頻度は不定とされている。OIDF カレンダー（[openid.net/calendar/](https://openid.net/calendar/)）の現時点表示でも 2024-06 の R&E WG エントリは確認できない。

本節では R&E WG の活動文脈に直接関係し、公開記録が残るプロセス上の議論を整理する。

### OIDF Federation ID4 パブリックレビュー（2024-06-01 開始）

6 月 1 日から開始された 45 日間のパブリックレビュー期間は、R&E セクターを含む OIDF 会員 364 名全体に対するコメント募集フェーズである。レビュー対象は draft 36 = [OpenID Federation 1.0 - ID4](https://openid.net/specs/openid-federation-1_0-ID4.html)。Sikt / Internet2 / GÉANT / SURF / GARR / SUNET 等の R&E セクターの OIDF 加盟組織はいずれもこの期間にレビュー意見を提出する権利を持っていた。実際にどの組織が意見を提出したか、また R&E WG メンバー間でレビュー方針について非同期議論が行われたかは公開記録からは追跡できない。

ただし、6 月後半の `openid/federation` GitHub リポジトリ整備（§2 参照）は、まさにこのレビュー期間中に外部からの意見投入経路を整える動きでもあり、結果的に 7 月末以降に集中する issue 投入（#18 / #19 / #22 / #23 / #24 / #25 等）の地ならしとなった。

### `openid-specs-ab` ML（Connect WG）の 6 月

Federation 仕様の上位 WG にあたる Connect WG の [`openid-specs-ab` ML 2024-June インデックス](https://lists.openid.net/pipermail/openid-specs-ab/2024-June/) は、6 月内に**わずか 4 投稿**のみという非常に静かな月だった。スレッド一覧:

1. **Public Review Period for Proposed Fourth Implementer's Draft of OpenID Federation**（Michael Jones、2024-06-02 04:51 UTC、[010328.html](https://lists.openid.net/pipermail/openid-specs-ab/2024-June/010328.html)）— OIDF 公式アナウンスの ML への転送。技術的議論は伴わない事務連絡
2. **Canceled event with note: AB/Connect WG (Pacific) @ Tue 2024-06-04 1am - 2am (GMT+2)**（Nat Sakimura、[010329.html](https://lists.openid.net/pipermail/openid-specs-ab/2024-June/010329.html)）— 6-04 開催予定の Pacific タイムゾーン WG コールが取り消された
3. **Issue #2157: OP RP-Initiated Logout and user's presence (openid/connect)**（Andrii Deinega、2024-06-05、[010330.html](https://lists.openid.net/pipermail/openid-specs-ab/2024-June/010330.html)）— RP-Initiated Logout 仕様がユーザー在席（オンライン状態）を前提としている点への疑問提起。Internet Identity Workshop で Mike Jones と議論した結果として Issue 化したとの経緯あり
4. **Issue #2158: Metadata parameter value arrays for RP metadata (openid/connect)**（Stefan Santesson、2024-06-14、[010331.html](https://lists.openid.net/pipermail/openid-specs-ab/2024-June/010331.html)）— RP メタデータパラメータが単一値しか取れない制約を、フェデレーション文脈で `[]` サフィックスの companion 配列パラメータとして拡張する提案。「This solution would be documented in an OpenID Federation metadata extension specification rather than modifying core federation documents」と明示

このうち **4 番目の Stefan Santesson のスレッドは Federation メタデータ拡張仕様という形態を取り、R&E Implementation Profile が将来採用しうるパターンと構造的に近い**点で注目に値する。R&E セクターでも複数の上流 IdP・下流 RP との接続を 1 つの RP メタデータで宣言する場面（典型例: 研究データリポジトリが複数の R&E IdP からのトークンを受容する場面）でこの問題は同様に発生する。同じ Issue 番号 #2158 は後の `openid/federation` の Issue #12（rohe による「Supported RP/client metadata parameters」、§5 参照）と問題意識が連続している。

`openid-specs-ab` の 6 月インデックスには、これら 4 投稿以外に Federation や R&E 関連の独立スレッドは確認できない。Connect WG 自身が 6-04 の Pacific コールを取り消すなど、6 月は欧米双方で会議活動が低調だった可能性が高い。

### R&E WG 定例コール

R&E WG 自身の 6 月中の定例コール開催の有無は、公式チャネル（openid.net/wg/rande/、`openid-specs-rande` ML）のいずれでも確認できない。openid.net/wg/rande/ のミーティング欄が「–」のままであり、ML 投稿は当月ゼロである。6 月は WG メンバーの中心層が (1) Federation ID4 のパブリックレビュー期間（6-01 開始）に対するレビュー作業、(2) GN5-1 WP5 配下の eduGAIN OpenID Federation PoC 実装作業、(3) 欧州夏季イベント（EIC 2024 が 6-04 〜 6-07 にベルリン、Identiverse 2024 が 5-28 〜 5-31 にラスベガス、TIIME 2024 は当年 1 月開催）の前後対応で多忙だった可能性が高い。WG 内部の非同期議論は、非公開の WG 定例チャネル、REFEDS Slack、GÉANT 内部 ML、GN5-1 WP5 confluence 等で進行していたと見られるが、外部からは追跡できない。

### 隣接コミュニティ: REFEDS OIDCre

REFEDS OIDCre Working Group（R&E WG の隣接 WG、SAML2 ⇔ OIDC 属性マッピング BCP を策定）の 2024 年 6 月の WG ミーティング開催記録は、REFEDS wiki 公開部分（[wiki.refeds.org/display/GROUPS/OIDCre](https://wiki.refeds.org/display/GROUPS/OIDCre)）からは直接確認できなかった。OIDCre が継続的に進めてきた REFEDS White Paper「SAML2 and OIDC Mappings」のコンサルテーションは当時並行して進行していた。

## 5. GitHub 上の議論

R&E WG の **OIDF 配下の公式** GitHub リポジトリは存在しない。openid.net/wg/rande/ にも公開リポジトリへの参照はない。

ただし、R&E WG が依拠する OpenID Federation 本体のリポジトリ [openid/federation](https://github.com/openid/federation) は、ID4 パブリックレビュー期間中の 6-18 〜 6-30 に **初期インフラ整備フェーズ**を迎え、当月内に 2 件の Issue（#12, #15）と 4 件の PR（#13, #14, #16, #17）が登録された。月単位の活動量としては Bitbucket 全盛時代と比べて GitHub への移行準備として大きな飛躍を示している。R&E セクター実装者が将来参照することになる仕様議論の入り口として、特に注目すべき 3 件を取り上げる。

### [openid/federation#12](https://github.com/openid/federation/issues/12) - Supported RP/client metadata parameters

- **開始日**: 2024-06-18
- **報告者**: rohe（Roland Hedberg、ID4 エディタの 1 人）
- **アサイン**: selfissued（Mike Jones）
- **マイルストーン**: Final
- **論点**: 現行 OIDC / OAuth2 仕様では、`token_endpoint_auth_method` のようなクライアントメタデータパラメータが**単一の希望値**しか取れない。直接登録（direct registration）ではこれで十分だが、**Federation 文脈では 1 つの RP が複数の AS と接続し、それぞれ異なるポリシーを持つ可能性がある**ため、希望値だけでなく「サポート可能な値の一覧」を宣言する必要がある
- **提案**: (1) `client_registration_types` を単数形 `client_registration_type` に改名（希望値を表現）、(2) `client_registration_types_supported` を新設して複数形（サポート可能値一覧）を表現、(3) 同様の `_supported` バリアントを他のメタデータパラメータにも追加する第一歩とする
- **構造的位置付け**: 6-14 に同月 `openid-specs-ab` ML に投稿された Stefan Santesson の Issue #2158（§3 参照）と問題意識が連続している。R&E セクターでも複数の上流 IdP / 下流 RP との多対多接続を 1 つの RP メタデータで宣言する場面で同様の問題が生じる
- **結果**: 当該 Issue は 2024-12-02 にクローズ（Final 化に向けた整理の中で対応）。`client_registration_types` の取り扱いは後年の draft 37 期にも複数 PR で検討された（例: 7-29 の `e4bb4199` コミット「Additional `client_registration_types` MAY be defined and used」）

### [openid/federation#15](https://github.com/openid/federation/issues/15) - [Introduction] This specs can be used beyond OpenID Connect and OAuth 2.0

- **開始日**: 2024-06-20
- **報告者**: peppelinux（Giuseppe De Marco、ID4 エディタの 1 人）
- **論点**: ID4 仕様の Introduction 節が「how to apply them when the underlying authentication protocol used is OpenID Connect or the underlying authorization protocol is OAuth 2.0」と限定的に記述している点への異議申し立て。De Marco は「OpenID Federation はプロトコル非依存（protocol-agnostic）であり、Connect / OAuth2 以外のプロトコル（具体的には Verifiable Credentials や Wallet エコシステム）にも適用できる」と主張し、Introduction にその明示記述を追加する提案を行った
- **背景**: 同 5 月 31 日付の Mike Jones ブログでも「Connect 以外のプロトコルにもトラスト確立の枠組みを適用できるようにするため、仕様名を OpenID Connect Federation から OpenID Federation へ改称した」と説明されており、Introduction 記述の改善はこの改称の趣旨を本文で完成させる作業
- **解決策**: 同 6-20 開始の PR #16「introduction improved, oidfed can be used with any other protocols」（`6c51ef6`）が対応として提出され、selfissued による code review 提案を反映した後、**2024-08-01 にマージ**された
- **R&E 文脈**: 「Connect / OAuth2 以外のプロトコル」の代表例として Verifiable Credentials / Wallet が想定されているが、R&E セクターでも将来 SAML2 シグナリング後段で Federation の信頼確立フレームのみを再利用するパターンが議論される可能性があり、Introduction の汎用化はその伏線となる

### `openid/federation` リポジトリ初期整備（PR #13 / #14 / #17）

技術的論争を伴わない整備作業だが、当月内の活動の主体を占めるため記録する。

## 6. 関連イベント

### OpenID Federation ID4 パブリックレビュー開始（2024-06-01）

§2 のとおり、当月最大の公式プロセスイベント。R&E WG が将来策定する R&E Implementation Profile の上位仕様の Implementer's Draft 化に向けた 45 日間レビューが、まさに当月開始された。

### Identiverse 2024（5-28 〜 5-31、ラスベガス）

R&E 直前文脈として、5 月末にラスベガスで開催された Identiverse 2024 のセッション群には OpenID Federation や Wallet トラスト関連の発表が複数含まれていた。R&E WG メンバー個別の登壇情報は当時の公式アジェンダから完全には追跡できないが、ID4 ラストコール終了（5-31）と日程が重なっており、業界全体としての Federation への注目が高まっていた時期に当たる。

### European Identity & Cloud (EIC) 2024（6-04 〜 6-07、ベルリン）

KuppingerCole 主催の EIC 2024 はベルリンで開催され、6 月のデジタルアイデンティティ業界最大の対面イベントの 1 つだった。R&E セクターからの登壇情報は公式アジェンダから完全には追跡できないが、Federation や eIDAS 2.0 / EUDI Wallet 関連の発表は多数含まれていた。R&E WG 議長 Vaghetti（GARR）や eduGAIN 関係者の参加可能性が高く、廊下談話レベルでの ID4 や R&E PoC に関する情報交換が行われていた蓋然性は高い。

### OpenID Foundation 6 月公開アナウンス

§2 のとおり、(1) 6-02 の Federation ID4 Public Review Period 告知、(2) 6-18 の Gail Hodges による [Digital Identity at the G20](https://openid.net/digital-identity-g20/) 投稿の 2 件のみ。後者は SIDI Hub 文脈で「教育・雇用資格の国境横断的可搬性」を 4 大優先ユースケースの 1 つに挙げており、間接的には R&E セクターとも接点を持つが、本文中に R&E WG・eduGAIN への直接言及はない。

### eduGAIN OpenID Federation PoC（GN5-1 WP5 配下、継続中）

GN5-1 WP5 配下で運営される PoC は、Q2 2024 開始時点から OpenID Federation を eduGAIN の将来トラスト技術として評価するもので、6 月時点で実装フェーズ序盤〜中盤にあった。9-17 の Trust and Identity Incubator Public Sprint Demo でツール群の対外公開デモが予定されており、6 月はその実装作業の準備期に当たる。R&E WG 議長 Vaghetti 本人が GARR の立場で PoC をリードしており、6-12 の `GEANT/edugain-openidfed` README.md 更新（§5 参照）はその公開トレースの 1 つである。Federation 仕様の ID4 パブリックレビュー開始は、PoC が評価する仕様基盤の「Implementer's Draft 直前段階」へのアップグレードを意味し、PoC にとってもタイムリーな前進だった。

### AARC TREE プロジェクト 3 か月目

[AARC TREE](https://aarc-community.org/aarc-tree-project/)（Authentication and Authorisation for Research and Collaboration – Technical Revision to Enhance Effectiveness）は 2024 年 3 月開始の EU 共同プロジェクトで、6 月時点で 3 か月目を迎えていた。AARC TREE の AARC Blueprint Architecture 改訂（AARC-BPA-2025）は **OpenID Connect と OAuth 2.0 を中心に据え、Proxy インターフェイスの SAML2 依存からの脱却**を打ち出している点で R&E WG の関心領域と直結する。6 月は WP3 Landscape analysis（D3.1、最終公開は 2024-12-31）の編集フェーズが進行中で、欧州夏季休暇前の作業初期フェーズだった。

## 7. 今後の予定（2024 年 6 月末時点の視点）

6 月末時点で R&E コミュニティが注視していた次月以降の動向は以下のとおり。

- **OpenID Federation 1.0 ID4 パブリックレビュー継続**: 6-01 開始のレビュー期間は 7-16 まで継続。意見投入の最終チャンスは 7 月前半
- **ID4 Notice of Vote 公告（7 月初頭予定）**: パブリックレビュー終了後の正式投票通知。早期投票 7-10、正式投票 7-17 〜 7-24 のスケジュールが既に予告済
- **`openid/federation` GitHub リポジトリでの作業継続**: 6 月後半に整備された GitHub Pages パイプラインと寄与プロセスのもとで、ID4 承認後の draft 37 編集フェーズに向けた issue / PR の活発化が予想される
- **eduGAIN OpenID Federation PoC の継続**: GN5-1 WP5 配下の検証作業継続。9 月の T&I Incubator Public Sprint Demo に向けた実装作業
- **NDN2024 / NORDUnet Conference 2024（2024-09-10 〜 12、ベルゲン）**: Trust and Identity トラックでの R&E WG 議長 Vaghetti の登壇予定
- **GÉANT Trust and Identity Incubator Public Sprint Demo（2024-09-17）**: eduGAIN OpenID Federation PoC ツールの対外向け初公開デモ予定
- **R&E WG 自身のドラフト整備**: OIDF 配下の公式仕様は引き続き「None yet.」のまま。OIDF 配下での対外可視性の改善は継続課題

6 月末時点での R&E WG の対外可視性は、OIDF 配下の ML・GitHub・ドラフトいずれにも公開アウトプットを残さない状態が継続している一方で、依拠する Federation 本体仕様が **ID4 パブリックレビュー入り**・**GitHub 作業基盤の整備開始**・**R&E セクター側 PoC の継続**という三重の前進を同月内に実現し、Sikt の Solberg がエディタとして関与し続けるという構造が当月のデータ分布から読み取れる。R&E 仕様策定の実体作業が OIDF 配下から GÉANT GN5-1 WP5 / Sikt / GARR / SURF 配下へ重心を移していく構造の前段階として、本月は「依拠仕様の最終投票直前段階への到達」と「議論基盤のオープン化」という双方の意味でマイルストーン的位置付けにある。
