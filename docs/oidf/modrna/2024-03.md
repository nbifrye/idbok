# OpenID Foundation MODRNA WG 活動レポート (2024年3月)

> 執筆日: 2026-05-22（遡及執筆）。本記事は 2024 年 3 月の MODRNA WG 活動を、約 2 年後の視点から `openid-specs-mobile-profile` メーリングリストの公開アーカイブ、`openid.net` 上の公開情報、および同月前後の OpenID Foundation 全体・隣接 WG・関連業界イベントの公表記録をもとに再構成したものである。MODRNA WG の議事録は non-public 運用のため、コール内の詳細議論は公開チャネル上には残っておらず、本記事は ML 公開アーカイブから読み取れる範囲の運用記録の整理を主としている。

## 1. 概要

MODRNA (Mobile Operator Discovery, Registration, & autheNticAtion) WG は、モバイルネットワークオペレータ (MNO) が OpenID Connect / OAuth 2.0 をベースに GSMA Mobile Connect 互換のアイデンティティサービスを提供するための相互運用プロファイルを策定する OpenID Foundation のワーキンググループである。共同議長は Bjorn Hjelm と John Bradley の 2 名、定例コールは隔週火曜 14:00-15:00 UTC（北米東部 10:00-11:00、北米太平洋 7:00-8:00、中央欧州 15:00-16:00。夏時間移行後は UTC 同一・北米/欧州側の現地時刻が前後する）のカデンスで運営され、議事録は non-public、仕様ソースは `bitbucket.org/openid/mobile/src/master/` で管理されている（`github.com/openid/` 配下に MODRNA WG の公式リポジトリは存在しない）。

2024 年 3 月の MODRNA WG は、公開チャネル上はきわめて静かな月であった。`openid-specs-mobile-profile` の公開アーカイブで本月にエントリが生成された週は **Week-of-Mon-20240325** の 1 週のみで、合計投稿は **3 月 26 日 (火) 13:22:08 UTC 投稿の 1 通**（[001955.html](https://lists.openid.net/pipermail/openid-specs-mobile-profile/Week-of-Mon-20240325/001955.html)、件名 "MODRNA WG Agenda"）に集約される。3/4・3/11・3/18 開始週のインデックス HTML は pipermail 上に生成されておらず、これは当該週の ML 投稿ゼロを意味する。

隔週火曜カデンス上、本月の定例コール候補日は **3 月 12 日 (火) と 3 月 26 日 (火)** の 2 回である。3 月 12 日コールは ML 上にアジェンダ投稿・キャンセル通知・議事サマリのいずれも観測されない「サイレント運用日」、3 月 26 日コールは Hjelm によるアジェンダ ML 投稿が確認できる定例開催日である。3/16-22 に IETF 119 Brisbane が開催されることから、3/12 候補日は IETF 119 直前期に、3/26 候補日は IETF 119 直後期にあたる。

本月の最大の特徴は、**3 月 26 日アジェンダ（[001955.html](https://lists.openid.net/pipermail/openid-specs-mobile-profile/Week-of-Mon-20240325/001955.html)）が、2024 年通年で公開チャネルから観測できる MODRNA WG アジェンダの中でも最も細目が充実した版** である点に集約される。標準 8 項目テンプレート（Roll Call / Adoption of the Agenda / External Organizations / Events / Specification Status / OpenID Certification for MODRNA / Issue Tracker / AOB）のうち、**External Organizations** と **Issue Tracker** の 2 項目に以下の合計 4 件の Bitbucket Issue / FAPI Issue 参照が明示されていた。

- **External Organizations の GSMA - Liaison Agreement update** サブ項目
- **External Organizations の CAMARA Project** サブ項目（参照先: Bitbucket Issue [#215 Android Carrier OpenID API](https://bitbucket.org/openid/mobile/issues/215/android-carrier-openid-api) ／ FAPI Issue [#630 Android Carrier OpenID API](https://bitbucket.org/openid/fapi/issues/630/android-carrier-openid-api) ／ FAPI Issue [#632 Security profile for CAMARA](https://bitbucket.org/openid/fapi/issues/632/security-profile-for-camara)）
- **Issue Tracker の CIBA Errata: Issue [#218 overstrict requirements on invalid_client](https://bitbucket.org/openid/mobile/issues/218/overstrict-requirements-on-invalid_client)** サブ項目

これらサブ項目は 2 月 27 日アジェンダ（[001953.html](https://lists.openid.net/pipermail/openid-specs-mobile-profile/Week-of-Mon-20240226/001953.html)）にも一部含まれていたが、3/26 アジェンダはそれを引き継ぎつつ Issue #218（CIBA Errata）を Issue Tracker の細目として正式に組み込んだ最初の例にあたる。Issue #218 自体は本月直前の **2 月 28 日 21:13 UTC に Joseph Heenan（Authlete／後の OpenID Certification 関係者）が ML へ起票投稿**（[001954.html](https://lists.openid.net/pipermail/openid-specs-mobile-profile/Week-of-Mon-20240226/001954.html)）したものであり、3/26 アジェンダへの組み込みは Heenan 起票への WG 議長側の応答に相当する。

本月時点では、これら 4 件のサブ項目はあくまで「コール上で口頭討議する論点リスト」として明示列挙されていたが、**翌 4 月 9 日アジェンダではすべてが脱落** することになり（参照: [2024 年 4 月レポート](./2024-04.md)）、結果として 3/26 アジェンダは 2024 年通年で「External Organizations と Issue Tracker のサブ項目が共に明示列挙された唯一の月」として位置づけられる。後の月から振り返ると、本月は MODRNA WG が GSMA Liaison・CAMARA・CIBA Errata の 3 系統論点を **ML 上のアジェンダで明示する運用** から、4 月以降の **アジェンダはヘッダ単独、細目は口頭討議へ寄せる運用** へとシフトする **転換点直前の月** に相当する。

### Issue #218（CIBA Errata 候補）の起点

3/26 アジェンダで CIBA Errata として明示された Issue #218 は、本月の MODRNA WG にとって **唯一の月内に登場した具体的 technical issue** である。起点となった ML 投稿は本月直前の 2 月 28 日 21:13 UTC、Joseph Heenan による [Week-of-Mon-20240226/001954.html](https://lists.openid.net/pipermail/openid-specs-mobile-profile/Week-of-Mon-20240226/001954.html) であり、本文の論旨は以下のとおりである。

- **論点**: CIBA Core 1.0 Final（2021-09 公開）§13 が `invalid_client` エラー応答に対し HTTP 401 ステータスコードを義務付けている
- **問題**: HTTP 401 は `WWW-Authenticate` ヘッダ同梱を要求するが、CIBA のクライアント認証方式は全てが challenge-response 型ではなく（例: `client_secret_post`、`private_key_jwt`、`tls_client_auth` 等）、`WWW-Authenticate` を意味的に発行できないケースが存在する
- **参照根拠**: RFC 6749 §5.2（OAuth 2.0 token endpoint のエラー応答）は HTTP 400 または HTTP 401 のいずれかを許容しており、CIBA Core も同様の柔軟性を持つべきである
- **提案**: CIBA Core §13 を Errata として緩和し、HTTP 400 / 401 のいずれも許容する

Heenan は OpenID Certification プログラムにおける CIBA Conformance Profile の実装にも携わっており、本論点は certification 観点での実装者間の摩擦から導かれたと推定される（ただし起票投稿本文には certification 文脈の明示記述はない）。

本投稿への ML 上の即時返信はなされず、3/26 アジェンダで Issue Tracker サブ項目として組み込まれることで WG コール内討議への持ち越しが確定した。Issue #218 はその後、本 2024 年中はクローズされず、後の **2025 年 1 月 30 日に Mike Jones / Joe DeCock が CIBA Core 1.0 errata 1 draft 化作業として `bitbucket.org/openid/mobile/pull-requests/18` で正式に編集対象に組み込む** ことになるが、本月時点では errata 化のための具体的なドラフト編集計画は ML 上には公開されていない。

### 推定される 3/26 コール内議題

議事録 non-public 運用下では、3/26 コール内の具体的議論を公開チャネルから直接確認することはできない。ただし、アジェンダ細目から推定される議題は以下のとおりである。

- **GSMA Liaison Agreement update**: GSMA は MODRNA WG の設立来の協業相手であり、Mobile Connect 仕様（GSMA 側仕様）と MODRNA WG 仕様群（MODRNA Authentication Profile、CIBA Core 等）の整合性維持に関する継続的な調整事項を扱う恒常的議題。本月の具体的アップデート内容は公開チャネルからは確認できない
- **CAMARA Project 連携 / Bitbucket Issue #215・FAPI #630**: Android Carrier OpenID API に関する MODRNA 側 Issue #215 と FAPI 側 Issue #630 の進捗共有。Android 上で MNO が提供する OpenID API を MODRNA WG 仕様群と FAPI WG 仕様群のどちらでカバーするかという責任分界点が論点と推定される
- **FAPI Issue #632 Security profile for CAMARA**: CAMARA プロジェクト向けに OAuth 2.0 / OpenID Connect ベースのセキュリティプロファイルを定義する FAPI 側 Issue。MODRNA WG にとっては自 WG 仕様（CIBA Core、MODRNA Authentication Profile）が CAMARA セキュリティプロファイルの参照標準として位置付けられる流れの一部
- **CIBA Errata Issue #218**: Joseph Heenan 起票の `invalid_client` 応答の HTTP 401 義務付け緩和提案。CIBA Core 1.0 Final 仕様の errata 化が必要かどうか、必要な場合の編集スケジュールが論点と推定される

これら 4 件のサブ項目はいずれも 4/9 アジェンダから脱落することから、3/26 コール内でいずれかの結論（解決済み / 次回以降に持ち越し / 議題から外す / 口頭討議のみに寄せる、のいずれか）が下された可能性が高いが、確定情報は公開チャネルからは取得できない。

## 5. GitHub 上の議論

MODRNA WG の仕様ソースは GitHub ではなく Bitbucket Cloud (`bitbucket.org/openid/mobile/src/master/`) で管理されている。GitHub 側に MODRNA WG の公式一次リポジトリは存在しない（`github.com/openid/MODRNA` といった誤記が一部で見られるが、そのようなリポジトリは現存しない）。

Bitbucket Cloud は SPA 描画のため外部からのクローリングに適さず、本稿の調査範囲では 3 月中の Bitbucket Issue / PR / コミット活動の網羅的件数を確認できない。ただし、(i) 3/26 アジェンダで明示されていた Bitbucket Issue #215 (Android Carrier OpenID API) ／ Issue #218 (CIBA Errata: overstrict `invalid_client`) の 2 件はいずれも本月時点で **オープン状態を維持** しており、ML 上に Bitbucket 由来のクローズ通知・新規 Issue 起票通知は流れていない、(ii) MODRNA WG の ML 上で 3 月中に Bitbucket 由来の自動通知メールが一切観測されない、(iii) 3/26 アジェンダの "Specification Status" 項目が `openid.net/wg/mobile/status/` への単純リンクに留まり具体的な版番号更新計画を欠くこと、から、Bitbucket 上でも本月は目立った新規動作はなかったと推定できる。

FAPI WG 側の Bitbucket Issue [#630 (Android Carrier OpenID API)](https://bitbucket.org/openid/fapi/issues/630/android-carrier-openid-api) と [#632 (Security profile for CAMARA)](https://bitbucket.org/openid/fapi/issues/632/security-profile-for-camara) は 3/26 MODRNA アジェンダに External Organizations 参照リンクとして含まれていたが、FAPI WG 側の本月の活動状況は MODRNA WG 月次レポートのスコープ外である。

なお、Atlassian による Bitbucket Cloud Issues / Wiki の 2026-08-20 完全廃止アナウンスは本時点（2024 年 3 月）では未公表（2026 年 3 月公表）であり、MODRNA WG として Issue Tracker 代替候補を検討する動きは本月の公開チャネルには存在しない。

### CAMARA プロジェクトの参照標準位置付け（背景）

Linux Foundation 配下の Telco API Alliance である CAMARA プロジェクトは、後の 9 月 16 日に予定する初の正式メタリリース（Meta-Release Fall24）に向けて API の品質検証・統合作業を進めていた期間。CAMARA Security and Interoperability Profile（[github.com/camaraproject/IdentityAndConsentManagement](https://github.com/camaraproject/IdentityAndConsentManagement)）は OAuth 2.0 / OpenID Connect 基本仕様群を基盤とし、特に OIDC Authorization Code Flow / CIBA / OAuth2 Client-Credentials / OAuth2 JWT Bearer の 4 フローをサポートする方針が確立していた。MODRNA WG にとって CIBA Core と MODRNA Authentication Profile は CAMARA セキュリティプロファイルの主要参照標準として位置づけられる関係にあり、3/26 MODRNA アジェンダで External Organizations の CAMARA Project サブ項目に FAPI Issue #632 (Security profile for CAMARA) が参照リンクとして明示されているのは、この相互参照関係を反映している。

OpenID Foundation は 2023 年 11 月以来 CAMARA の Associate Member として参加しており、本月時点で MODRNA WG・FAPI WG・eKYC-IDA WG の 3 WG が CAMARA 関連論点を並行追跡している。

## 7. 今後の予定（2024 年 3 月末時点の視点）

3 月末時点の公開情報からは、MODRNA WG の 4 月以降の明示的な予定は ML・`openid.net` いずれにも掲載されていない。隔週カデンスと月内事象から推定される事項は以下のとおり。

- **定例コール**: 隔週火曜サイクル（3/12 サイレント、3/26 開催）に従えば、4 月の候補日は 4 月 9 日（火）と 4 月 23 日（火）の 2 回。4 月 9 日は OIDF Workshop Sunnyvale（4/15）および IIW XXXVIII Mountain View（4/16-18）の直前週にあたり、アジェンダ投稿が期待される — 実際に 4/9 アジェンダ ML 投稿として実現する（ただし External Organizations / Issue Tracker サブ項目はすべて脱落した "骨組み版" となる、参照: [2024 年 4 月レポート](./2024-04.md)）
- **OpenID Foundation Workshop（2024-04-15、Sunnyvale, Google）**: 本月時点で MODRNA WG Update 枠（15 分枠）の登壇が想定される。Bjorn Hjelm の登壇が後に確認される
- **OSW 2024 (2024-04-10〜12, Rome)** / **IIW XXXVIII (2024-04-16〜18, Mountain View)**: WG コアメンバーの対面参加見込み
- **CAMARA Project 連携の継続**: Bitbucket Issue #215 (Android Carrier OpenID API)、FAPI Issue #630・#632 (Security profile for CAMARA) の各 Issue は本月時点でいずれもオープン状態を維持。CAMARA Meta-Release Fall24（9/16 予定）に向けた CAMARA Security and Interoperability Profile の確定作業が並走する見込み
- **CIBA Errata Issue #218 の取り扱い**: Joseph Heenan 起票（2/28）の `invalid_client` HTTP 401 義務付け緩和提案について、CIBA Core 1.0 errata 化に進めるか、編集対象 / スケジュール / レビュー手順の確定が次月以降の論点となる見込み — 実際には本年中はクローズされず、2025 年 1 月 30 日の Mike Jones / Joe DeCock による CIBA Core 1.0 errata 1 draft 化作業（`bitbucket.org/openid/mobile/pull-requests/18`）に持ち越されることになる
- **Implementer's Draft 群の現状維持**: MODRNA Authentication Profile ID1 / Account Porting ID1 / User Questioning API ID2 はいずれも次版改訂の公式アナウンスがなく、現行ステータスを維持

3 月の対外可視な活動は (i) 議長 1 名による 3/26 コール用アジェンダ ML 投稿 1 通（External Organizations / Issue Tracker サブ項目を明示列挙した "詳細版"）、(ii) IETF 119 Brisbane 開催週を含む 3 週連続の ML サイレント運用、の 2 点に集約される。当時の読者にとっては「IETF 119 開催月でありながら MODRNA ML 上の活動は 3/26 アジェンダ投稿 1 通に集約された静粛な月」として記憶される月であり、後の月から振り返ると、本月は **4 月 9 日以降に確立する「アジェンダはヘッダ単独、細目は口頭討議」運用への転換点直前の月** として位置づけられる。
