# OpenID Foundation IPSIE WG 活動レポート (2026年2月)

**執筆日: 2026-04-18**（2026年2月分の遡及執筆）

## 1. 概要

IPSIE WG（Interoperability Profile for Secure Identity in the Enterprise）は、企業向けの安全なアイデンティティ連携の相互運用性プロファイルを策定するOpenID Foundation の Working Group である。2026年2月は毎週火曜日（9:00 AM PST）に定例ミーティングを4回開催した。

2月の主要テーマは **SL2（Security Level 2）におけるセッション終了プロトコルの設計**であった。Karl McGuinness が実装アプローチの比較分析を主導し、「全セッション一括終了」対「IdP でのユーザー再認証要求」という二つのアプローチをめぐる議論が全会期にわたって続いた。また、SCIM（System for Cross-domain Identity Management）の機能要件ドラフト整備と IETF データトラッカー提出の準備が並行して進んだ。

## 2. 公開された仕様・ドラフト改訂

2026年2月に新たな仕様版の公開は確認できなかった。

WG が採択済みのドラフトとして以下が引き続き参照された：

- **IPSIE Common Requirements Profile**
- **OpenID Connect SL1 Profile**（Draft 00、2025年9月発行）
- **SCIM AL1 Profile**（ライフサイクル管理、作業継続中）

## 3. ミーティングと議論

### 2026-02-03（定例）

**参加者**: Aaron Parecki (Okta)、Danny Zollner (Okta)、Karl McGuinness、JD Pawar、Jen Schreiber、Dick Hardt (Hellō)、Bertrand Carlier、Ameya Hanamsagar、Sirisha Kotikalapudi、Shannon Roddy、Bjorn Hjelm (Yubico)、George Fletcher

**SCIM 進捗**: Jen Schreiber が Danny Zollner を SCIM ドキュメントの共著者として確認した。3月の IETF 会合（深圳）への提出を目標とするが、完了の確実性は未定とされた。

**SL2 セッション終了**: 実装複雑性をめぐる議論が長時間に及んだ。Karl は比較分析文書を翌週までに提出すると確約した。2つの主要アプローチが浮かび上がった：

- **「全セッション一括終了」アプローチ**: IdP がすべてのセッションを即座に無効化
- **「ユーザー再認証要求」アプローチ**: IdP が次アクセス時にユーザーへ再認証を促す

George Fletcher はより細粒度の制御を主張し、セッション全体を一括処理するのではなく、セッション個別の終了が望ましいと提案した。モバイルアプリシナリオと企業デプロイメントにおける既存プロトコルの限界も指摘された。

**決定事項**: セッション終了機能は SL2 に留める。「セッション有効期限切れ」コマンド機能を含めつつ、完全に新しいプロトコル開発は要しない範囲で設計を進める。

**アクションアイテム**:

- Karl McGuinness: 比較分析文書の完成
- Aaron Parecki: 議論を反映した Levels ドキュメントの更新（翌週レビュー向け）

### 2026-02-17（定例）

**参加者**: Aaron Parecki、Danny Zollner、George Fletcher、Mark McGuire、Bertrand Carlier、Karl McGuinness、Jen Schreiber、Travis Tripp、Dick Hardt

**SCIM の取り扱い**: SCIM ドラフトは SCIM WG での採択後に SCIM WG 組織へ移管することを前提に、当面 IPSIE リポジトリ内で管理することを決定した。Danny は2種類のドキュメント作成を計画した：

1. 機能要件（AL1/AL2/AL3）を記述するドキュメント
2. 各レベルが参照するプロトコル仕様ドキュメント

**SL2 セッション終了（Karl McGuinness 資料レビュー）**: Karl が作成した実装アプローチ比較文書を全体でレビューした。主な論点：

- 「コマンド（command）」という用語を採用することで合意（他の候補語より明確）
- セッション終了の結果として想定される2種類の挙動を整理：
  - **セッション再検証（session revalidation）**: ユーザーに再認証を求める
  - **包括的失効（comprehensive revocation）**: すべてのアクセスを無効化
- 本作業が扱うのは**認証バインディング**のみであり、認可・パーミッションは対象外であることを明確化
- SL2 要件の全体スコープに含める内容と範囲外とする内容の切り分けを議論

**決定事項**:

- SCIM ドラフトは当面 IPSIE リポジトリに置く
- セッション操作の用語として「command」を採用
- セッション再検証と全アクセス失効の概念的区別を仕様に明記

**アクションアイテム**:

- Karl McGuinness: セッション終了ドキュメントの論点リストを作成し GitHub ブランチを更新
- 全参加者: Karl の GitHub ブランチをレビューし フィードバックを提供

（[議事録 2026-02-17](https://github.com/openid/ipsie/wiki/2026%E2%80%9002%E2%80%9017) より）

### 2026-02-24（定例）

**参加者**: Aaron Parecki (Okta)、George Fletcher、Dick Hardt、Mike Kiser、Tom Jones、Danny Zollner、JD Pawar、Karl McGuinness、Sirisha Kotikalapudi、Jen Schreiber、Sean O'Dell、Ameya Hanamsagar

**アクションレシート（Action Receipts）**: Sean O'Dell（Shared Signals Foundation）が「指示的イベント（prescriptive events）は完了または未完了の確認を要求する」というコンセプトを提案した。Karl McGuinness は、このスキームは Shared Signals Framework に属するものであり、IPSIE はそれを参照する形にすべきだと主張した。スキーマ文書は「1〜2週間以内」に提出予定とされた。

**SCIM スコープの粒度問題**: 単一の `scim` スコープで十分か、それとも `scim.read` のような細粒度のスコープが必要かをめぐって議論が起きた。

- Karl McGuinness: 広いスコープは権限委譲の問題を生じさせるとして、クライアントクレデンシャル管理の複雑性を排除するため JWT プロファイルを推奨した
- 参加者間で実装上の現実として細粒度スコープが望ましい場面があることも認識された

**SCIM ロール vs グループ**: Danny Zollner がプロファイルで SCIM グループとロールの両方を対象とすべきかを提起した。現実の SCIM 実装はアプローチが多様で、ロール割り当て機能すら持たないものもある。Karl は SCIM のロールモデリングの限界により実装上の回避策が発生している現状を指摘した。

**セッション終了の最新化**: Karl がセッションライフサイクルドキュメントの更新を発表した。`prompt=login` および `max_age` パラメータで実現できる動作に対して、各プロトコルにわたって用語の統一を試みた。

**その他**:

- 3月3日の定例コールは Aaron Parecki の不在により中止
- 3月10日・17日は Dick Hardt が議長を務める

（[議事録 2026-02-24](https://github.com/openid/ipsie/wiki/2026%E2%80%9002%E2%80%9024) より）
