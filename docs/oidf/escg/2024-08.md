# OpenID Foundation Ecosystem Support CG 活動レポート (2024年8月)

> 執筆日: 2026-05-20（遡及執筆）

## 1. 概要

Ecosystem Support Community Group（以下「ESCG」）は、Open Banking / オープンデータ / デジタルアイデンティティ等の各種エコシステムが OpenID Foundation の仕様（FAPI、OpenID Connect、OpenID4VC ファミリー等）を実装・プロファイリングする際の実装者支援を目的とする CG である。共同議長は Dima Postnikov（ConnectID / OIDF Vice Chair）、Ralph Bragg（Raidiam）、Mark Verstege（OIDF Corporate Representative）の 3 名で、これに Mark Haine（OIDF Technical Director）、Gail Hodges（OIDF Executive Director）を加えた 5 名が Founding Proposers として [CG ページ](https://openid.net/cg/ecosystem-support-community-group/) に記載されている。CG の正式ローンチは 2025 年 7 月 23 日付ブログ [OIDF launches Ecosystems Support Community Group](https://openid.net/oidf-launches-ecosystems-support-community-group/) を待つ。

2024 年 8 月は ESCG が公的にも技術的にも **完全に未発足** の月である。CG 名義の ML・GitHub リポジトリ・公式ページ・議事録のいずれにも、ESCG という呼称・構想・準備活動の痕跡は一切確認できない。本月のレポートは、ローンチまで約 11 ヶ月先に立つ時点の状況を、ESCG の前駆コンテクスト（複数エコシステムが OIDF 仕様を採用する地ならし）に直接連関する関連 WG / CG の活動として再構成する。

具体的には以下のとおりである:

- メーリングリスト `openid-ecosystem-support` の [公開 pipermail アーカイブ](https://lists.openid.net/pipermail/openid-ecosystem-support/) は最古の週次インデックスが `Week-of-Mon-20250825`（2025 年 8 月 25 日週）であり、2024 年 8 月分の週次エントリは存在しない（リスト自体が 8 月時点で未開設の蓋然性が極めて高い）
- GitHub リポジトリ [`openid/cg-ecosystem-support`](https://github.com/openid/cg-ecosystem-support) は「This repository is empty」の表示が継続しており、8 月時点で commits / issues / PRs / discussions すべて 0 件
- 共同議長 3 名・Founding Proposers 5 名の体制、組織原則（Sharing / End User Privacy and Consent / Security / Interoperability / Respect 等）の公的提示はいずれも 8 月時点で未実施
- ESCG という呼称が公開チャネル上のいずれかに登場する最初のタイミングは、本月 **2024 年 8 月 13 日付** で公開された [Registration Open for OpenID Foundation Hybrid Workshop at Microsoft on Monday, October 28, 2024](https://openid.net/registration-oidf-workshop-cisco-october-28-2024/) における Workshop アジェンダの 1 セッション「15 min Ecosystem CG/WG Brainstorming Session」（Dima Postnikov 主導、Mark V., Elcio (TBC)）である。本セッションは 10-28 Workshop での **15 分のブレインストーミング枠** に過ぎず、設立提案でも準備会合でもない。それでも本月時点で「Ecosystem CG/WG」というラベルが OIDF の公開アジェンダに初めて姿を現したという意味で、本月は ESCG の前史において重要な節目に該当する
- OIDF Board 議事録は non-public のため、Board レベルでの当該テーマ初期検討が 8 月のどのタイミングで進行していたか（あるいは進行していなかったか）は確定できない

すなわち 8 月は、後の ESCG に直接連なる「Ecosystem CG/WG」という公的ラベルが Workshop アジェンダ上に初めて出現したという 1 点を除き、ESCG 名義の活動としては公開記録ゼロ の月と位置付けられる。本レポートでは、本月に外部から確認できる ESCG 前駆コンテクストの痕跡を、関連 WG / CG の活動として誠実に再構成する。

特筆すべき 8 月の OIDF 全体の出来事は **(a) Shared Signals 3 仕様（Shared Signals Framework 1.0 / Continuous Access Evaluation Profile 1.0 / CAEP Interoperability Profile 1.0）の Implementer's Draft 承認（8 月 20 日、Approve 74 / Object 1 / Abstain 21）、(b) OpenID Federation Wallet Architectures 1.0 の AB/Connect WG 採択 Call for Adoption 開始（8 月 6 日、Michael Jones 起案、Brian Campbell 等から強い反対）、(c) OpenID Federation -37 ドラフト公開（8 月 7 日、GitHub 移行後初版）、(d) AuthZEN Authorization API 1.0 draft 00 公開（8 月 14 日）と Implementer's Draft レビュー期間の延期決定（8 月 21 日、Omri Gazitt）、(e) GAIN POC CG の進捗アップデート公開（8 月 19 日、OpenID4VCI / SD-JWT VC 相互運用デモ報告）、(f) 10-28 Workshop アジェンダ初公開（8 月 13 日、Ecosystem CG/WG Brainstorming セッションを含む）、(g) eKYC-IDA Family の ISO PAS Submission ドラフトコメント募集（8 月 29 日、Hodari McClain）、(h) OpenID Connect Core / Discovery / Dynamic Client Registration 3 仕様の ISO/IEC FDIS ballot 開始（8 月 21 日、後の ISO/IEC 26131〜26133 化に直結）** の 8 件である。いずれも ESCG 名義の活動ではないが、後に ESCG が支援対象として扱うことになる中核仕様群と、複数エコシステム展開の制度的足場が、8 月時点で並走で前進していた状況を示す。

## 2. 公開された仕様・ドラフト改訂

ESCG は仕様策定をスコープ外とする CG であり、また 8 月時点で CG 自体が未発足のため、ESCG 名義の公開ドキュメント・チャーター文書はいずれも存在しない。

8 月の OIDF 仕様パイプラインのうち、ESCG が後に関心領域として持つ「複数エコシステムが OIDF 仕様を実装・プロファイリングする」状況に直接関係するものは以下:

- **2024 年 8 月 20 日** [Three Shared Signals Implementer's Drafts Approved](https://openid.net/three-shared-signals-implementers-drafts-approved/) — Marie Jordan（OIDF Secretary）署名による Shared Signals WG 成果物 3 仕様の Implementer's Draft 化承認アナウンス。承認された仕様は (i) OpenID Shared Signals Framework 1.0、(ii) OpenID Continuous Access Evaluation Profile 1.0、(iii) CAEP Interoperability Profile 1.0。投票結果は Approve 74 / Object 1 / Abstain 21（参加 96 / 全 379 メンバー、25% 参加でクォーラム 20% を上回る）。Early voting 開始 8 月 5 日、本投票期間 8 月 12 日 〜 8 月 19 日 12:00 PT。Implementer's Draft は実装者への IP プロテクションを伴う安定版であり、Enterprise SSO / Workforce Identity エコシステム（後の IPSIE WG の核となる領域）の中核仕様の 1 つが本月に IP 保護段階へと進んだ
- **2024 年 8 月 7 日** [OpenID Federation -37 published](https://lists.openid.net/pipermail/openid-specs-ab/2024-August/010369.html) — Michael Jones（AB/Connect WG Co-Chair）による Federation ドラフト -37 公開。「Implementer's Draft 4 以降の最初のドラフト」かつ「GitHub への移行（[openid/federation](https://github.com/openid/federation)）後初版」と位置付けられる。IANA designated experts からの pending registration request に関するフィードバックを反映
- **2024 年 8 月 14 日** [Authorization API 1.0 – draft 00](https://openid.net/specs/authorization-api-1_0-00.html) 公開 — AuthZEN WG が成果物として Authorization API 1.0 の draft 00 を初公開。Policy Decision Point (PDP) と Policy Enforcement Point (PEP) が互いの内部実装を知ることなく認可リクエスト・決定を交換できる API を定義。PDP が提供し PEP が呼び出す Evaluation endpoint を中核とする。本ドラフトは Identiverse 2024 interop の target だった
- **2024 年 8 月 21 日（ISO/IEC FDIS ballot 開始）** OpenID Connect Core 1.0、OpenID Connect Discovery 1.0、OpenID Connect Dynamic Client Registration 1.0（いずれも Errata Set 2 incorporating 版）について、ISO/IEC JTC 1 における DIS が FDIS として登録され、8 週間の FDIS ballot 期間が開始（〜 9 月 18 日）。後の [ISO/IEC 26131:2024](https://www.iso.org/standard/89056.html) / [ISO/IEC 26132:2024](https://www.iso.org/standard/89057.html) / [ISO/IEC 26133:2024](https://www.iso.org/standard/89059.html) として 10 月 1 日に出版される過程の重要マイルストーン
- **2024 年 8 月 6 日 〜 19 日** [Call for Working Group Adoption of OpenID Federation Wallet Architectures 1.0](https://lists.openid.net/pipermail/openid-specs-ab/2024-August/010353.html) — Michael Jones 起案による 2 週間 (8-06 〜 8-19) の WG 採択 Call for Adoption。Federation Wallet Architectures は「Italian wallet deployment の現行プラクティスを記録」した仕様として位置付けられ、初版本文は Giuseppe De Marco のリポジトリ [peppelinux/federation-wallet](https://github.com/peppelinux/federation-wallet) で参照可能。Jones は「This specification is a starting point - not an endpoint」と明言。8 月の本 Call は強い反対（後述 §4）を集めて未収束のまま終わり、9 月 13 日の 2nd Call for Adoption（前回フィードバック反映版）へと持ち越された

8 月の OIDF 仕様パイプラインは、(a) Shared Signals 3 仕様の Implementer's Draft 化、(b) Federation -37 公開と Wallet Architectures 1.0 採択論争、(c) AuthZEN draft 00 公開、(d) OpenID Connect 3 仕様の ISO/IEC FDIS ballot 開始 という **4 系統が並走** し、エコシステム実装者にとっての中核仕様群が同月に複数の進捗マイルストーンを迎えた月であった。

## 4. メーリングリストの主要スレッド（関連 WG の動向）

`openid-ecosystem-support` ML（[親アーカイブ](https://lists.openid.net/pipermail/openid-ecosystem-support/)）は 8 月時点で公開アーカイブにエントリがなく、ESCG 名義の ML 議論は確認できない。代わりに、後に ESCG が扱うことになる仕様・エコシステム領域に関する 8 月の主要 ML 議論を、関連 WG（AB/Connect / FAPI / AuthZEN / Shared Signals / DCP / eKYC-IDA）の公開アーカイブから選定して整理する。

### 4.1 [Call for Working Group Adoption of OpenID Federation Wallet Architectures 1.0](https://lists.openid.net/pipermail/openid-specs-ab/2024-August/010353.html) - 2024-08-06 開始

Michael Jones が起案した OpenID Federation Wallet Architectures 1.0 の WG 採択 Call for Adoption スレッド。AB/Connect ML 8 月アーカイブで最大級の議論を集めた（メッセージ番号 010353 周辺の長大なスレッド、25 件以上の返信）。Jones は「This specification is a starting point - not an endpoint」とし、Italian wallet deployment の現行プラクティス記録版として位置付けた。

主要論点と立場:

- **Giuseppe De Marco（ドラフトエディタ）の論旨**（[010377](https://lists.openid.net/pipermail/openid-specs-ab/2024-August/010377.html) 等）: ドラフトの核となる目的は「trust infrastructure の実装方法明確化、特にメタデータ secure exchange」とし、(i) wallet コンテクストでは "client" 用語が不適切（issuance では wallet を、presentation では verifier を指してしまう）として "openid_wallet_relying_party metadata" への置換を提案、(ii) OpenID4VCI が signature 検証のための public key をメタデータに含めていない点（SD-JWT VC 以外のフォーマット採用時の implementer 混乱の原因）への対処、(iii) 信頼できる party からの verifiable endpoint 取得と endpoint randomization（adversarial redirection 防止）の 2 つの functional requirement への対処、を挙げる
- **Brian Campbell の強い反対**（[010381 "Oppose Adoption"](https://lists.openid.net/pipermail/openid-specs-ab/2024-August/010381.html)、2024-08-13）: 「substantive objections を解決せずに adoption に進むこと」への懸念表明。Joseph Heenan が「特定のメタデータ値は別仕様で定義すべきではないか」と問題提起し、long-term 方向性は合意があるものの「他仕様で定義されるまで採択を待つべきか、採択後に解決すべきか」のタイミング論で対立。Bjorn Hjelm は「メタデータパラメータは将来別仕様で定義し参照する旨の editor's note 追記」を提案し、議長 Nat Sakimura は当該 non-normative update への同意を表明したが、Campbell は「legitimate concerns は relocation/removal で事後対処するのではなく substantive resolution が先」との立場を譲らなかった
- **未収束**: 8-19 の Call 期間終了時点で明確なコンセンサスに到達せず、9 月の 2nd Call for Adoption（前回フィードバック反映版）に持ち越された

ESCG の文脈から見ると、本スレッドは **後に ESCG が支援対象とする「複数ウォレットエコシステム（Italian wallet を含む EU 各国）が Federation 経由で相互運用する基盤仕様」** が、8 月時点で AB/Connect WG 内で激しい論争の渦中にあった事実を記録する。Italian wallet deployment という特定エコシステムの実装プラクティスをどの程度仕様に取り込むべきか、という論点は、ESCG が後に直面する「個別エコシステムの実装経験を OIDF 仕様にどう還元するか」という構造的論点の典型事例である。

### 4.2 [AuthZEN Authorization API 1.0 - roadmap](https://lists.openid.net/pipermail/openid-specs-authzen/2024-August/000191.html) - 2024-08-21 投稿

Omri Gazitt（Aserto CEO / AuthZEN WG Co-Chair）による Implementer's Draft レビュー期間の延期決定アナウンス。WG が受け取った substantive feedback の 2 主要領域は:

1. **Schema-Friendly Improvements**: 現代的な development toolchain への対応強化（strongly-typed protobuf / gRPC contract、strongly-typed JSON schema、改善された OpenAPI representation）
2. **Request Ordering Preservation**: 1.1 でバッチリクエストの順序保持のため、`evaluations` フィールドを map から array へ遷移（fail-fast error handling 等のシナリオ対応）

Co-chairs は「breaking change を後追いで強いるような Implementer's Draft 公開を回避する」ため、初回 Implementer's Draft レビュー期間を延期。必要最小限の変更案を 9-03 ミーティングでレビュー予定とした。なお 8-27 ミーティングはチーム可用性制約で cancel。

ESCG の文脈から見ると、本投稿は **後に ESCG が支援対象とする「Enterprise / Workforce Identity 領域における Authorization エコシステム」** の中核仕様が、8 月時点で「実装者 friendly な schema」と「Implementer's Draft の質的保証」のトレードオフを抱えていた事実を示す。延期決定は後の 9-17 〜 11-01 のパブリックレビュー期間、10-24 Notice of Vote、11-15 承認に直結する。

### 4.3 [Final issues and PRs for FAPI2 Security Profile](https://lists.openid.net/pipermail/openid-specs-fapi/2024-August/003171.html) - 2024-08-27 投稿

Dave Tonge（FAPI WG Co-Chair）による FAPI 2.0 Security Profile Final 化に向けた最終 PR 群のレビュー依頼。3 件の PR が対象:

- **PR #514 (Security Consideration)**: CISA レビュー文書から提起された key compromise 関連の推奨事項対処。stateful vs stateless credential approach の表現について vendor フィードバックを募集
- **PR #513 (Conformance Note)**: 新 BCP195 iteration への準拠タイミングに関する implementer 向けガイダンス追加
- **PR #512 (Editorial Update)**: FAPI 2 Security Analysis 文書への参照追加

加えて同月の関連 Issue として #706（FAPI2 security profile §5.4 の不明瞭、dag.sneeggen 8-09 起票、Judith Kahrer 返信）、#707（TLS cipher suites リストが過度に restrictive、dag.sneeggen 起票）、#708（FAPI2SP で URL query への access token 受け渡しが明示的に禁止されていない、josephheenan 起票）が ML に流れている。

ESCG の文脈から見ると、これら FAPI 2.0 系の最終調整論点は **後に ESCG が支援対象とする「FAPI 2.0 を採用するエコシステム」（UK Open Banking、Brazil Open Finance、Australia Consumer Data Right 等）が依拠する Final 候補仕様** の調整が、8 月末に CISA レビュー対応を含めて大詰めを迎えていた事実を示す。Tonge は後の 9-02 集中起票（FAPI Issue #709 〜 #717）の主要起票者でもある。

### 4.4 [What is the state of the conformance tests?](https://lists.openid.net/pipermail/openid-specs-digital-credentials-protocols/Week-of-Mon-20240819/000426.html) - 2024-08-19 起案

Richard Esplin が DCP WG ML 上で起案した DCP WG conformance tests の状態に関する問い合わせスレッド（5 返信）。Joseph Heenan、Marcos Caceres、Richard Esplin 間で OpenID4VCI / OpenID4VP の conformance test 整備状況についてやり取りが行われた。

ESCG の文脈から見ると、本スレッドは **後に ESCG が支援対象とする「OpenID4VC ファミリーを採用するエコシステム」（EUDI Wallet 各国実装、Japan Trust Service Forum 周辺等）の adoption に直結する conformance test 整備** が、8 月時点で DCP WG 内のオープン論点として顕在化していた事実を示す。

### 4.5 [Identity Assurance Specification Family ISO PAS Submission RFC](https://lists.openid.net/pipermail/openid-specs-ekyc-ida/Week-of-Mon-20240826/000864.html) - 2024-08-29 投稿

Hodari McClain による eKYC-IDA 1.0 仕様ファミリーの ISO PAS Submission ドラフトのコメント募集投稿。Google Docs で共有された ドラフトに対して inline コメントを募り、9 月中旬までのフィードバック完了を依頼。「OpenID Foundation would like to formally submit the package to ISO once the review period for final is up in September」と明言。

ESCG の文脈から見ると、本投稿は **後に ESCG が支援対象とする「eKYC / Identity Assurance を採用する各国規制エコシステム（KYC 規制下の金融機関、デジタル ID 規制下のオンラインサービス）」** の中核仕様が、8 月末に ISO PAS 提出準備段階に入っていた事実を示す。後の eKYC-IDA Final 化（10-03 承認）と ISO PAS 化は、ESCG の支援領域となる「複数法域の Identity Assurance 規制との整合」の前駆動向に該当する。

### 6.1 OIDF Hybrid Workshop @ Microsoft 登録開始（2024-08-13）

### 6.2 GAIN POC CG アップデート公開（2024-08-19）

[GAIN Community Group: An Update](https://openid.net/gain-community-update/)（2024-08-19 公開）により、GAIN POC CG が 2 年にわたる 3 回の成功した demonstration cycle（最新サイクルは OpenID for Verifiable Credential Issuance / IETF SD-JWT VC profile を中心）の進捗を公表。参加組織は Bundesdruckerei、Meeco、Talao、Datev、Authlete、Boruta 等で、credential issuance / wallet integration の相互運用性デモを実施。今後 OpenID for Verifiable Presentations への展開と、Open Identity Exchange との Trust Framework metadata（OpenID Federation 使用）連携を予告。

ESCG の文脈から見ると、GAIN POC CG は **「OIDF 仕様を採用する複数エコシステム間の相互運用性」を実証してきた先行 CG** であり、後に ESCG がより広範な「エコシステム支援」を担う際の参照モデルに該当する。8 月時点で GAIN POC CG が「複数エコシステム実装の OIDF への valuable feedback」を継続的に生成していた事実は、ESCG が後に同種の機能をより制度化された形で担うことになる前提状況を示す。

### 6.3 OpenID Connect 3 仕様の ISO/IEC FDIS ballot 開始（2024-08-21）

ISO/IEC JTC 1 における OpenID Connect Core 1.0、Discovery 1.0、Dynamic Client Registration 1.0（いずれも Errata Set 2 incorporating 版）の DIS が FDIS として登録され、8 週間の FDIS ballot 期間が開始（〜 9 月 18 日）。後の [ISO/IEC 26131:2024](https://www.iso.org/standard/89056.html) / [ISO/IEC 26132:2024](https://www.iso.org/standard/89057.html) / [ISO/IEC 26133:2024](https://www.iso.org/standard/89059.html) 化（10 月 1 日出版）に直結する。

ESCG の文脈から見ると、OpenID Connect 中核仕様の ISO/IEC 化は **「複数法域の規制エコシステムが OIDF 仕様を国際標準として参照する」基盤の確立** に該当する。後に ESCG が「複数法域の規制エコシステムとの整合」を支援する際、ISO/IEC 化された OpenID Connect は最も参照容易な基準スタックの 1 つとなる。
