# OpenID Foundation Ecosystem Support CG 活動レポート (2024年5月)

> 執筆日: 2026-05-21（遡及執筆）

## 1. 概要

Ecosystem Support Community Group（以下「ESCG」）は、Open Banking / オープンデータ / デジタルアイデンティティ等の各種エコシステムが OpenID Foundation の仕様（FAPI、OpenID Connect、OpenID4VC ファミリー等）を実装・プロファイリングする際の実装者支援を目的とする CG である。共同議長は Dima Postnikov（ConnectID / OIDF Vice Chair）、Ralph Bragg（Raidiam）、Mark Verstege（OIDF Corporate Representative）の 3 名で、これに Mark Haine（OIDF Technical Director）、Gail Hodges（OIDF Executive Director）を加えた 5 名が Founding Proposers として [CG ページ](https://openid.net/cg/ecosystem-support-community-group/) に記載されている。CG の正式ローンチは 2025 年 7 月 23 日付ブログ [OIDF launches Ecosystems Support Community Group](https://openid.net/oidf-launches-ecosystems-support-community-group/) を待つ。

2024 年 5 月は ESCG が公的にも技術的にも **完全に未発足** の月であり、CG 名義の ML・GitHub リポジトリ・公式ページ・議事録のいずれにも、ESCG という呼称・構想・準備活動の痕跡は一切確認できない。本月のレポートは、ローンチまで約 14 ヶ月先に立つ時点の状況を、ESCG の前駆コンテクスト（複数エコシステムが OIDF 仕様を採用する地ならし）に直接連関する関連 WG / CG の活動として再構成する。

公開チャネルの状態を整理すると以下のとおりである:

- メーリングリスト `openid-ecosystem-support` の [公開 pipermail アーカイブ](https://lists.openid.net/pipermail/openid-ecosystem-support/) は最古の週次インデックスが `Week-of-Mon-20250825`（2025 年 8 月 25 日週）であり、2024 年 5 月分のエントリは存在しない（リスト自体が 5 月時点で未開設の蓋然性が極めて高い）
- GitHub リポジトリ [`openid/cg-ecosystem-support`](https://github.com/openid/cg-ecosystem-support) は「This repository is empty」状態であり、5 月時点で commits / issues / PRs / discussions すべて 0 件
- 共同議長 3 名・Founding Proposers 5 名の体制、組織原則（Sharing / End User Privacy and Consent / Security / Interoperability / Respect 等）の公的提示はいずれも 5 月時点で未実施
- ESCG という呼称が公開チャネル上のいずれかに登場する最初のタイミングは、後の 2024 年 8 月 13 日付で公開された [10-28 Workshop 登録ページ](https://openid.net/registration-oidf-workshop-cisco-october-28-2024/) における Workshop アジェンダの「15 min Ecosystem CG/WG Brainstorming Session」であり、本月から見て 3 ヶ月先の出来事である

5 月時点で最も「ESCG の前駆コンテクスト」に直接該当する公的事象は、**2024 年 5 月 16 日** 付で Gail Hodges（OIDF Executive Director、後の ESCG Founding Proposer）が CFPB Director Rohit Chopra 宛に送付した [Letter to the CFPB on US Open Banking](https://openid.net/letter-cfpb-open-banking/) である。本レター単体で、Section 1033 ルールメイキングにおいて「データ形式標準」とは別に「Communication Protocol 標準」を Qualified Industry Standard (QIS) として参照すべきこと、FAPI が「12 か国以上で採用され、2,800 件の認証実装と数十億の API コール実績」を持つ Communication Protocol 候補であることを正式に表明している。後の 7-24 公開の [Guidance to the CFPB regarding US Open Banking](https://openid.net/open-banking-guidance-to-cfpb/)（Hodges / Heenan / Postnikov / Haine / Leszcz / Garber 6 名連名）に至る一連の対外発信のうち、本レターは 5 月時点における起点に位置する。

特筆すべき 5 月の OIDF 全体の出来事は **(a) Mastercard の OIDF Board 加盟（5 月 13 日公示、Sustaining Member 昇格）、(b) Hodges の CFPB Letter（5 月 16 日付、FAPI を QIS Communication Protocol として正式推薦）、(c) OpenID Federation 第 4 Implementer's Draft の Working Group Last Call (WGLC) 開始（5 月 13 日、Michael Jones 起案）、(d) FAPI 2.0 Security Profile の WGLC 進行（5 月 1 日、Rifaat Shekh-Yusef 起動）と FAPI 1.0 の ISO PAS 提出議論、(e) Identiverse 2024 Las Vegas（5 月 28 〜 31 日、AuthZEN 9 ベンダー 14 実装の Interop と OIDF Board Insights パネル）、(f) AuthZEN WG の Identiverse Interop イベント実施（5 月 28 日 Las Vegas、9 ベンダー参加）、(g) DCP WG の Identiverse 内 Hybrid Meeting 開催（5 月 29 日、Kristina Yasuda 主催）、(h) eKYC-IDA WG の Identiverse 内 Hybrid Meeting 開催（5 月 29 日）** の 8 件である。いずれも ESCG 名義の活動ではないが、後に ESCG が支援対象として扱うことになる中核仕様群（FAPI 2.0、Federation ID4、OpenID4VC、AuthZEN）と、複数エコシステム展開の制度的足場（CFPB Letter、Mastercard Board 加盟）が、5 月時点で **同時並行で前進していた** 状況を示す。

## 2. 公開された仕様・ドラフト改訂

ESCG は仕様策定をスコープ外とする CG であり、また 5 月時点で CG 自体が未発足のため、ESCG 名義の公開ドキュメント・チャーター文書はいずれも存在しない。

5 月の OIDF 仕様パイプラインのうち、ESCG が後に関心領域として持つ「複数エコシステムが OIDF 仕様を実装・プロファイリングする」状況に直接関係するものは以下:

ESCG という呼称が公開チャネル上のいずれかに登場する最初のタイミングは、後の 2024 年 8 月 13 日付で公開された [10-28 Workshop 登録ページ](https://openid.net/registration-oidf-workshop-cisco-october-28-2024/) における Workshop アジェンダの「15 min Ecosystem CG/WG Brainstorming Session」（Dima Postnikov / Mark V. ### 3.3 5-16 CFPB Letter の ESCG 前史としての位置付け（最重要）

[Letter to the CFPB on US Open Banking](https://openid.net/letter-cfpb-open-banking/)（Gail Hodges、2024-05-16、CFPB Director Rohit Chopra 宛）は、ESCG 前史において **2024 年で最も重要な単一文書** に位置付けられる。レターの要旨は以下のとおりである:

- **「データ形式標準」と「Communication Protocol 標準」の役割分担**: データ形式標準は naming conventions / standard codes / formatting / data models / schema を扱い、Communication Protocol はセキュリティ・プライバシー・技術的相互運用性を担保する。両者は別個の技術領域であり、Rule 1033 の最終ルールでは **両者を別個の QIS として参照すべき**
- **FAPI の QIS Communication Protocol としての推薦**: OAuth 2.0 + OpenID Connect プロファイルである FAPI が、UK・Australia・Brazil・Saudi Arabia 等 **12 か国超で採用**、グローバルで **2,800 件以上の FAPI 実装が認証取得済み**、**数十億規模の FAPI API コール実績**
- **Communication Protocol 標準が不在の場合の 4 リスク**: (i) 相互運用性の崩壊（実装ごとに分散すれば 3rd party developer の負担が増し競争が減退）、(ii) Time to Market の悪化（Saudi Arabia は明確な標準により 12 ヶ月未満で FAPI 展開を達成）、(iii) セキュリティテスト不足、(iv) クロスボーダー Open Banking 取引における US 単独の断片化リスク
- **OIDF ガバナンスの CFPB 要件適合性**: OIDF の governance model は CFPB 要件を満たすこと、ギャップがあれば good faith で埋める姿勢、NIST との協議および CFPB スタッフとの直接協議を提案
- **2023-12-29 提出文書の follow-up**: CFPB NPRM (Personal Financial Data Rights) への OIDF 既提出意見書のフォローアップ

本レターの ESCG 前史的意義は以下:

- **後に ESCG が支援対象とする「複数法域 Open Banking エコシステムへの FAPI 採用支援」を OIDF 最上層が米国規制当局相手に正式表明した最初の公的文書**: 後に ESCG が「12 グローバルエコシステムへの Open Banking 実装支援」を主たる活動軸とすることになるが、その米国セグメント分の公的表明が本レターで完成
- **後の 7-24 CFPB Guidance ブログの直接の前段**: 5-16 のレターから 69 日後に公開される [Guidance to the CFPB regarding US Open Banking](https://openid.net/open-banking-guidance-to-cfpb/)（Hodges / Heenan / Postnikov / Haine / Leszcz / Garber 6 名連名）は、本レターの論点を more technical / more granular に展開した姉妹文書に該当する蓋然性が高い
- **後の ESCG Founding Proposer 5 名のうち Hodges 単独の起案であった事実**: 5 月時点では Hodges 個人の対外発信であり、Postnikov / Bragg / Verstege / Haine は本レターの正式署名者として登場しない。後の 7-24 Guidance では Postnikov・Haine・Leszcz が連名に加わる。**5-16 から 7-24 にかけての 69 日間に「Hodges 単独表明 → 複数 Founding Proposer 連名」へと OIDF 上層部内部での体制構築が進んだ** 様子が時系列から読み取れる

ただし本レター単体は ESCG 設立の準備活動でも告知でもない。あくまで「OIDF が複数法域 Open Banking 支援を Executive Director 主導で米国規制当局相手に公的表明した」という限定的事例である。

### 3.4 5-13 Mastercard Board 加盟の ESCG 前史としての位置付け

[OIDF Welcomes Mastercard to the Board](https://openid.net/mastercard-joins-oidf-board/)（2024-05-13 公示）は、Mastercard が 2022 年から OIDF Corporate Member として複数 WG に参加してきた経緯を踏まえ、**Sustaining Member として OIDF Board 入り** したことを公示するブログである。

- **Adam Sommer**（VP of Security Standards、ペイメント業界 20 年）が Mastercard 一次代表として Board に着任
- **Mark Andrus**（Director, Industry, Policy & Standards Engagement）が alternate として着任
- Gail Hodges コメント: 「Mastercard have long been leaders in the Identity space and benefit from years of experience building rails that power global payments」

ESCG 前史的意義は以下:

- **「グローバルペイメントレールを動かす実績を持つ事業者」が OIDF Board に正式に加わった事実**: 後に ESCG が支援対象とする「複数 Open Banking エコシステム」の中核実装者として Mastercard が Board 内発信力を獲得。本加盟の 3 日後に Hodges が CFPB Letter を発出していることから、**Mastercard Board 加盟と CFPB Letter は同じ「Open Banking エコシステム支援強化」という戦略的方向性の同時帰結** と読める
- **ペイメント業界実績の OIDF 戦略への組み込み**: 後の ESCG が扱うことになる「Open Banking / Open Finance / Wallet 連携」の各領域で、Mastercard が Board レベルで関与する体制が 5 月時点で整った

## 4. メーリングリストの主要スレッド（関連 WG の動向）

`openid-ecosystem-support` ML（[親アーカイブ](https://lists.openid.net/pipermail/openid-ecosystem-support/)）は 5 月時点で公開アーカイブにエントリがなく、ESCG 名義の ML 議論は確認できない。代わりに、後に ESCG が扱うことになる仕様・エコシステム領域に関する 5 月の主要 ML 議論を、関連 WG（AB/Connect / FAPI / AuthZEN / DCP / eKYC-IDA）の公開アーカイブから選定して整理する。

### 4.1 [Working Group Last Call - FAPI 2 Security Profile](https://lists.openid.net/pipermail/openid-specs-fapi/2024-May/) - 2024-05-01 投稿

Rifaat Shekh-Yusef による FAPI WG ML への WGLC 起動投稿。FAPI 2.0 Security Profile を Implementer's Draft から **Final 仕様へ進めるための Working Group Last Call** を正式に開始した。WGLC 期間中、Dave Tonge・Joseph Heenan・Nat Sakimura らが集中的に Issue 起票（#690-#698、本月のうち 9 Issue が新規起票）し、特に Joseph Heenan による [Issue #698: TLS vulnerability](https://lists.openid.net/pipermail/openid-specs-fapi/2024-May/) は WGLC 期間中に発見された TLS 関連の脆弱性論点として、Final 化に向けた具体修正の起点となる。

### 4.2 [FAPI 1.0 ISO PAS Submission Draft](https://lists.openid.net/pipermail/openid-specs-fapi/2024-May/) - 2024-05-01 投稿

Hodari McClain（OIDF）による FAPI 1.0 を **ISO Publicly Available Specification (PAS) として提出するためのドラフトレビュー依頼**。Michael Jones による follow-up 返信、Hodari McClain による再返信、Gail Hodges による意見表明、Michael Jones による「FAPI 2 Explanatory Report for ISO PAS」関連投稿の連鎖。

ISO PAS は、業界コンソーシアムが策定した標準を ISO 標準として fast track 採択するためのプロセスである。FAPI 1.0 が ISO 標準になることで、各国規制当局は「ISO 標準を参照する」という形式で FAPI を組み込みやすくなる。

ESCG の文脈から見ると、本ドラフトレビューは **後に ESCG が支援対象とする「規制エコシステムが FAPI を採用する際の標準参照コスト」を引き下げる戦略的整備** として位置付けられる。CFPB Letter（5-16）が「OIDF の governance model は CFPB 要件を満たす」と主張する論拠の 1 つが ISO 標準化プロセスへの進入であり、5 月の ISO PAS Submission Draft 化と CFPB Letter は **同じ戦略の両輪** として読むことができる。
