# OpenID Foundation Ecosystem Support CG 活動レポート (2024年11月)

> 執筆日: 2026-05-19（遡及執筆）

## 1. 概要

Ecosystem Support Community Group（以下「ESCG」）は、Open Banking / オープンデータ / デジタルアイデンティティ等の各種エコシステムが OpenID Foundation の仕様（FAPI、OpenID Connect、OpenID4VC ファミリー等）を実装・プロファイリングする際の実装者支援を目的とする CG である。共同議長は Dima Postnikov（ConnectID / OIDF Vice Chair）、Ralph Bragg（Raidiam）、Mark Verstege（OIDF Corporate Representative）の 3 名で、これに Mark Haine（OIDF Technical Director）、Gail Hodges（OIDF Executive Director）を加えた 5 名が Founding Proposers として CG ページに記載されている。CG の正式ローンチは 2025 年 7 月 23 日付ブログ [OIDF launches Ecosystems Support Community Group](https://openid.net/oidf-launches-ecosystems-support-community-group/) を待つ。

2024 年 11 月は ESCG という呼称も構想も、公開された OIDF チャネル上には**一切登場していない月**である。ESCG の名称が外部公開資料で初めて確認できるのは 2025 年 1 月 14 日付 [2025 OpenID Foundation Board of Directors](https://openid.net/2025-openid-board-of-directors/) のボード選挙結果アナウンス内、Mark Verstege 紹介文の「Mark has been a key supporter of the newly formed Ecosystem Community Group to help ecosystems develop and share best practices.」という一文であり、それより 2 ヶ月以上前の 11 月時点では:

- メーリングリスト `openid-ecosystem-support` の [公開 pipermail アーカイブ](https://lists.openid.net/pipermail/openid-ecosystem-support/) は最古の週次インデックスが `Week-of-Mon-20250825`（2025 年 8 月 25 日週）であり、11 月分の週次エントリは存在しない（リスト自体が 11 月時点で未開設の蓋然性が極めて高い）
- GitHub リポジトリ [`openid/cg-ecosystem-support`](https://github.com/openid/cg-ecosystem-support) は「This repository is empty」の表示が継続しており、11 月時点で commits / issues / PRs / discussions すべて 0 件（後の 2026-05-04 に owner により archived 化）
- CG ページ [openid.net/cg/ecosystem-support-community-group/](https://openid.net/cg/ecosystem-support-community-group/) の公開時期は外部から確定できないが、11 月時点では openid.net 内の他記事から本ページへの導線案内は一切確認できない
- 共同議長 3 名・Founding Proposers 5 名の体制、6 つの組織原則（Sharing / End User Privacy and Consent / Security / Interoperability / Respect / Lower Cost of Deployment）の公的提示はいずれも 11 月時点では未実施
- OIDF Board 議事録は non-public のため、Board レベルでのチャーター承認手続きが 11 月のどのタイミングで進行していたか（あるいは進行していなかったか）は確定できない

すなわち 11 月は、ESCG が OIDF の対外公開資料上にも関連 ML・GitHub・議事録上にも一切痕跡を残していなかった月であり、12 月以降の ESCG 助走期間よりさらに 1 ヶ月先行する **最も初期の前駆コンテクストの月** である。本月の関連活動はもっぱら「ESCG が後にスコープに含めることとなるエコシステム横断的な動きを、OIDF の他の WG が個別に扱っていた」という形でしか観察できない。本レポートでは、11 月に外部から確認できる ESCG 前駆コンテクストの痕跡を、ローンチ前 8 ヶ月超の助走期間の出発点として誠実に再構成する。

特筆すべき 11 月の OIDF 全体の出来事は **(a) OpenID4VP 第 3 Implementer's Draft 45 日間パブリックレビュー開始（11 月 1 日）、(b) FAPI 2.0 Conformance Tests への DPoP サポート追加公示（11 月 7 日）、(c) IPSIE WG 創設プロセスに関する公式釈明（11 月 14 日）、(d) AuthZEN Authorization API 1.0 Implementer's Draft 承認（11 月 15 日付、Approve 82 / Object 2 / Abstain 22）、(e) AB/Connect WG における OpenID4VP の準備状況をめぐる論争（11 月 18 日〜19 日）、(f) FAPI WG の Errata 運用方針確認（11 月 27 日コール）** の 6 件である。いずれも ESCG 名義の活動ではないが、後に ESCG が支援対象として扱うことになる OpenID4VC ファミリー・FAPI 2.0 認証テスト・AuthZEN といった中核仕様群が、11 月時点でちょうど Implementer's Draft 化・認証拡張・パブリックレビュー開始という重要マイルストーンを並走で迎えていた状況を示す。

## 2. 公開された仕様・ドラフト改訂

ESCG は仕様策定をスコープ外とする CG であり、また 11 月時点で CG 自体が未発足のため、ESCG 名義の公開ドキュメント・チャーター文書はいずれも存在しない。

11 月の OIDF 仕様パイプラインのうち、ESCG が後に関心領域として持つ「複数エコシステムが OIDF 仕様を実装・プロファイリングする」状況に直接関係するものは以下:

- **2024 年 11 月 1 日** [Public Review Period for Proposed Implementer's Draft of OpenID4VP Specification](https://openid.net/public-review-period-for-proposed-third-implementers-draft-of-openid-for-verifiable-presentations-specification-3/) — Marie Jordan 署名による DCP WG 成果物の 45 日間パブリックレビュー開始公示（2024-11-01 〜 2024-12-16）。対象は OpenID4VP 第 3 Implementer's Draft 候補版 [draft 22](https://openid.net/specs/openid-4-verifiable-presentations-1_0-22.html)。本改訂の主要な技術変更点は次の 3 件で、いずれもエコシステムの実装互換性に直接影響する:
  - **Digital Credentials Query Language の導入**: 従来の Presentation Exchange に代わる新たなクレデンシャル問い合わせ言語。「実装者からのフィードバックを特に歓迎する」と公示で明記されており、後の本投票（2024-12-17 〜 2024-12-24）に向けた重要論点
  - **Transaction Data メカニズム**: ユーザー認証/識別と認可を紐付ける機構。決済または Qualified Electronic Signature による文書署名等のユースケースを射程に入れる
  - **`client_id_scheme` の再構成**: 独立パラメータとしての `client_id_scheme` を廃止し、`client_id` 自体のプレフィックスとして統合。先行版で指摘されていたセキュリティ懸念への対応
- **2024 年 11 月 7 日** [FAPI 2.0 Conformance Tests Now Support DPoP](https://openid.net/fapi-2-0-conformance-tests-support-dpop/) — Mike Leszcz（OIDF Operations Director）公示。FAPI 2.0 Conformance Tests に RFC 9449（DPoP）サポートを追加。ベータテスト期間を経た正式提供であり、`DPoP nonce` サポートを含む。これにより FAPI 2.0 Security Profile の `mTLS or DPoP` 二択の sender-constrained access token 検証が両方向で証跡化可能となり、Open Banking 系エコシステム（Brazil / UK / Australia / Saudi Arabia 等）が FAPI 2.0 Final（後の 2025-02-22 公開）へ移行する際の認証取得経路が 11 月時点で確立した
- **2024 年 11 月 15 日** [AuthZEN Authorization API 1.0 Implementer's Draft Approved](https://openid.net/authzen-authorization-api-1-0-implementers-draft-approved/) — Marie Jordan 署名による AuthZEN WG 成果物の承認公示。投票結果は **Approve 82 票、Object 2 票、Abstain 22 票、合計 106 票**（参加率 27%、20% クォーラム要件超過）で成立。本投票期間は 2024-11-07 〜 2024-11-14（12:00 PT）、Early voting 開始 2024-10-31、Notice of Vote 公示は 2024-10-24 付（[Notice of Vote](https://openid.net/notice-of-vote-implementers-draft-authzen-authorization-api-1-0/)）。Specification は [Authorization API 1.0-01](https://openid.net/specs/authorization-api-1_0-01.html) として公開

11 月の OIDF 仕様パイプラインは、**(a) OpenID4VP 第 3 Implementer's Draft のパブリックレビュー開始、(b) FAPI 2.0 Conformance Tests の DPoP 対応拡張、(c) AuthZEN Authorization API 1.0 Implementer's Draft の承認** という、後に ESCG が「複数エコシステムに同一の OIDF 仕様スタックを提供する CG」として支援対象とする 3 系統（Verifiable Credential / Open Banking 系 API セキュリティ / Authorization API）が同時並行で前進した月である。OpenID4VP と FAPI 2.0 と AuthZEN という 3 系統の進展が 11 月に並走していたことは、後の 2025 年 1 月以降の ESCG 設立構想の素地が技術仕様面で 11 月時点で既に整いつつあったことを示す。

## 4. メーリングリストの主要スレッド（関連 WG の動向）

`openid-ecosystem-support` ML（[親アーカイブ](https://lists.openid.net/pipermail/openid-ecosystem-support/)）は 11 月時点で公開アーカイブにエントリがなく、ESCG 名義の ML 議論は確認できない。代わりに、後に ESCG が扱うことになる仕様・エコシステム領域に関する 11 月の主要 ML 議論を、関連 WG（FAPI / AB/Connect）の公開アーカイブから選定して整理する。

### 4.1 [The OID4VP is not ready for implementation](https://lists.openid.net/pipermail/openid-specs-ab/2024-November/010502.html) - 2024-11-19 開始

AB/Connect WG 公開 ML 上で、Tom Jones が「OpenID4VP は holder の informed consent に関する最低要件を満たしておらず、Verifiable Presentation は実装準備が整っていない」と問題提起したスレッド。投稿では既存の法的枠組みおよび ACM Ethics ドキュメントとの整合性を論点に、`openid/OpenID4VP` Issue #333 を参照根拠として挙げた。応答は Joseph Heenan（[010503.html](https://lists.openid.net/pipermail/openid-specs-ab/2024-November/010503.html)）に限定され、長大な論争へは発展しなかった。

このスレッドは、後の 2024-12-03 付 [Notice of Vote](https://openid.net/notice-of-vote-for-proposed-implementers-draft-of-openid-for-openid-for-verifiable-presentations/) で OpenID4VP 第 3 Implementer's Draft が本投票（12-17 〜 12-24）に進む前の **パブリックレビュー期間（11-01 〜 12-16）中盤に公開された数少ない技術的問題提起** であり、後の ESCG が「複数エコシステムが OpenID4VP を実装・プロファイリングする際の holder consent 要件をどう扱うか」を論点に据える前段にあたる。Tom Jones 自身は ESCG メンバーではないが、ESCG が後に支援対象とすることになる「Verifiable Credential エコシステムの consent モデル設計」の論点が、11 月時点で公の場に持ち出されていた事実は記録に値する。

### 4.2 [Spec Call Notes 18-Nov-24](https://lists.openid.net/pipermail/openid-specs-ab/2024-November/010499.html) - 2024-11-18 公開

AB/Connect WG の 11 月 18 日定例コール議事録（Michael Jones 公開、参加者 7 名: George Fletcher, Nat Sakimura, Mike Jones, Brian Campbell, David Waite, Tom Jones, Aaron Parecki）。主要議題:

- **Native SSO 仕様**: Mike Jones が PR #742 をレビュー予定。Final 化を巡る議論で、Brian Campbell が「`id_token` を hint として使う際に標準外の検証ルールに依存することへの違和感」を表明。一方で「顧客が見れば実装を求めることになる」ため慎重な準備が必要との認識で一致。Okta および Yahoo 等の複数ベンダーが既に実装済みであることが確認された
- **モバイル領域の追加作業の必要性**: George Fletcher が問題提起したが、MODRNA WG の現状活動がコール参加者間で明確に把握されていない状況が露呈
- **GitHub リポジトリ管理**: WG 配下 4 リポジトリの状況確認。`federation-wallet` は 14 件の open issue を抱え、一部は仕様 adoption 前の遺残。Mike Jones が #39〜#42 のレビューと主リポジトリリスト更新を引き受け
- **OpenID4VP**: 11-01 開始のパブリックレビュー中。Tom Jones が「ユーザー consent モデル」への懸念を表明し、Mike Jones は「実行可能なフィードバックは正式な issue として提出を」と要請

### 4.3 [Spec Call Notes 25-Nov-24](https://lists.openid.net/pipermail/openid-specs-ab/2024-November/010505.html) - 2024-11-25 公開

AB/Connect WG の 11 月 25 日定例コール議事録（Michael Jones 公開、参加者 5 名: Nat Sakimura, Mike Jones, Aaron Parecki, Tim Cappalli, Tom Jones）。主要議題:

- **AI ノートテイカー対応**: Mike Jones が複数の AI ノートテイカー bot のコール参加を拒否。「オフレコ議論の可能性を保護する」ためで、OIDF 全体としての bot 参加ポリシーは未策定との認識
- **OpenID Connect RP Metadata Choices**: 「Multi-valued parameters are for requests and not responses」を扱う PR がコミュニティフィードバックを反映して承認・公開
- **Native SSO 仕様**: マージされた PR により 3 つの既存 issue が解決見込み。「実装は `id_token` 状態を真に必要としているのか、それとも device secret に依存できるのか」が論点として提起
- **OpenID Federation 更新**: 2 件のクラリフィケーションが承認 — (1) federation entity の鍵が metadata に含まれないことの明示、(2) `Request Object` の authorization endpoint および PAR endpoint での利用方法。クライアント認証方式の透明性および metadata の競合解決ルールに関する 2 件の open issue がフィードバック募集中
- **OpenID4VP consent**: Tom Jones が「Verifiable Presentation は holder informed consent の最低要件を満たさない」とする ACM ethics 標準への参照を改めて提起

### 4.4 [Errata or dot-release](https://lists.openid.net/pipermail/openid-specs-fapi/2024-November/003229.html) - 2024-11-28 開始

FAPI WG 公開 ML 上で、Nat Sakimura が 11-27 付 FAPI WG コールでの質問への回答として投稿したスレッド。前日コールで「normative changes（規範的変更）を errata ドキュメントに含めてよいのか」が議題に挙がっており、Sakimura は「可能である」と確認した上で、OpenID Connect Core 仕様での先例として「Self-Issued `sub` 計算におけるセキュリティ問題が Errata 1 で修正された」事実を引用した。

このスレッドは、後の **FAPI 2.0 Security Profile Final 化（2025-02-22）後の Errata 1 公示（2025-02-25 付 [Notice of a Security Vulnerability](https://openid.net/notice-of-a-security-vulnerability/) に伴う CVE-2025-27370 / CVE-2025-27371 修正）** の運用方針が 11 月時点で WG 内で確立していたことを示す。ESCG の文脈から見ると、本論点は「複数エコシステムが Final 化済み仕様を実装した後にセキュリティ修正を反映させる際の正式手順」が、11 月時点で OIDF 内で明文化されていたことを意味する。後に ESCG が支援対象とする FAPI 2.0 移行時の運用課題（Final 後の errata 適用）の前提条件が、11 月コール起点で整理された。

FAPI WG 公開 ML 上で、Nat Sakimura が Australian Consumer Data Right (CDR) のパブリックコンサルテーション「AU Consumer Data Right Rules – non-bank lending and banking data scope」を共有したスレッド。締切は 2024-12-24、参照先は treasury.gov.au。

ESCG の文脈から見ると、本通知は **後に ESCG 共同議長を務める Mark Verstege（Consumer Data Right (AU) における Lead Architect for Information Security and Banking）の所掌領域である Australian CDR の規制改定が 11 月時点で公的協議段階にあった事実** を示す。CDR は ESCG が後に「Open Banking エコシステム」の典型例として扱う規制スキームの 1 つであり、その規則改定協議が FAPI WG の公開 ML を経由してコミュニティに共有されたことは、Open Banking エコシステムと FAPI WG の連携が 11 月時点で定常運用に乗っていたことを裏付ける。本通知自体は ESCG に一切言及していないが、ESCG が後にカバーする「規制 ↔ 仕様」連携の典型的な情報経路を示す。

## 5. GitHub 上の議論

GitHub リポジトリ [`openid/cg-ecosystem-support`](https://github.com/openid/cg-ecosystem-support) は **2024 年 11 月時点で空または未作成** である。リポジトリの正確な作成時期は外部から確定できないが、GitHub UI 上は「This repository is empty」と表示され、Issues / Pull Requests カウントは 0 のまま。11 月中の commits / issues / pull requests / discussions は **すべて存在しない**。

ESCG の前駆となるリファレンスアーキテクチャ構想（Dima Postnikov 個人が後に EIC 2025 / Identiverse 2025 で発表する素材、Ralph Bragg が Raidiam で蓄積した UK Open Banking / Brazil Open Banking のセキュリティプロファイル知見、Mark Verstege の Consumer Data Right (AU) Lead Architect 経験等）は、11 月時点では各人の個人・所属組織のチャネル（個人ブログ・社内ドキュメント・カンファレンス資料）に分散して存在していた可能性が高いが、ESCG という統合枠組みでの公開ホスティングは GitHub・OIDF Confluence いずれにおいても 11 月時点では未実現である。

関連 WG リポジトリ側では、AB/Connect WG の `OpenID4VP` リポジトリで Issue #333 が 11-19 の Tom Jones による ML 投稿で参照される等、後に ESCG が支援対象とすることになる Verifiable Credential エコシステムの consent モデル設計議論が、11 月時点で個別 issue として個別 WG 内に分散して進行していた。これらは ESCG 名義の議論ではないが、ESCG が後に「複数エコシステム横断で同一仕様の実装を支援する」役割を担う際に集約されるべき議論の **11 月時点での分散状態のスナップショット** にあたる。

## 6. 関連イベント（ESCG が後に扱うエコシステム動向）

### 6.1 IPSIE WG 創設プロセスへの公式釈明（2024-11-14 公開）

[For the Record: The IPSIE WG and OpenID Foundation Processes](https://openid.net/ipsie-wg-and-oidf-processes/) は、10 月 15 日に発表された Interoperability Profiling for Secure Identity in the Enterprise (IPSIE) Working Group の創設プロセスに関する一部メディア報道の誤解への OIDF からの公式釈明である（無署名、OIDF 名義）。要旨:

- 新 WG 提案には「OIDF アクティブメンバー最低 5 名」が必要で、IPSIE は 7 名の Proposers を擁していた
- WG の作業内容を単一エンティティが支配することはなく、複数メンバー組織間の協働として運営される
- IPSIE は work in progress であり、Final 仕様も市場投入製品もまだ存在しない
- コンセンサスは WTO ガイドラインに沿った標準策定のコアバリュー
- 「メンバーがメディア・マーケティングで OIDF プロセスをどう語るか」に関するポリシーギャップがあったことを認め、是正の必要を示唆

ESCG の文脈から見ると、本釈明は **OIDF が 11 月時点で「新 WG/CG の創設プロセスに関する対外的な透明性確保が課題である」と公的に認識していた事実** を示す。後の ESCG 創設（2025-07-23 ローンチ）に向けた手続きにおいて、ESCG は Working Group ではなく Community Group の形態を選択し、より軽量なガバナンスでローンチされることになるが、その背景には 11 月時点の IPSIE 釈明で露呈した「WG 創設プロセスへの対外的なコンセンサス形成」の難しさへの認識が含まれていた可能性がある（明示の証拠はなく推定）。

### 6.2 2025 OIDF Community Representatives Election 指名期間（2024-11 末時点）

11 月時点では 2025 Community Representatives 選挙の指名期間は未開始である（指名期間開始は 2024-12-09）。任期満了対象は Nat Sakimura および John Bradley の 2 議席で、いずれも 2025-01-16 を新任期開始日とする選挙が 12 月以降に予定されていた。

本選挙の結果公示（2025-01-13）および 2025-01-14 付 [2025 OpenID Foundation Board of Directors](https://openid.net/2025-openid-board-of-directors/) 記事の中で、Mark Verstege 紹介文に「the newly formed Ecosystem Community Group」が初めて公の場に登場する。すなわち 11 月は、**ESCG への公的言及の起点となる 1 月 14 日付 Board アナウンスの 2 ヶ月前**にあたり、選挙手続き自体もまだ開始されていない段階である。Mark Verstege 自身は 2024-01-17 公示の 2024 Board 選挙結果で Corporate Representative として 2 年任期に当選しており、11 月時点で任期 1 年目の終盤を OIDF Board メンバーとして過ごしていた。

### 6.3 AuthZEN Authorization API 1.0 承認の意義（2024-11-15）

§2 で扱った AuthZEN Authorization API 1.0 Implementer's Draft 承認は、ESCG のスコープ（Open Banking 系エコシステム支援）とは直接重ならないが、**OIDF が 11 月時点で 4 つの仕様ファミリー（OpenID Connect, FAPI, OpenID4VC, AuthZEN）を並列で Implementer's Draft 〜 Final ステージへと進める運用モデルを定常化させていた** ことを示す。後に ESCG がエコシステム横断的支援を担う際の「複数仕様への並列対応」の運用前例が、11 月時点で OIDF 全体として確立していた。

ESCG に関しては 11 月時点で公開された設立・運用開始予定の告知は確認できない。「newly formed Ecosystem Community Group」という公の呼称が初めて使われる 2025 年 1 月 14 日付 Board アナウンスまで約 2 ヶ月、CG ページが公の場から案内されるのも 2025 年 1 月中旬以降、ESCG への呼称言及を含む WG ブログ（2025-03-19 付 FAPI WG ブログ）までは約 4 ヶ月、第 1 回コール開催日（2025-07-28）や正式ローンチアナウンス（2025-07-23）の予告は 11 月末時点では一切公開されていない。
